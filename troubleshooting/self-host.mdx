Find the symptom and open it. Most answers start with the backend's log:

```bash
docker compose logs --tail 200 postqueen
```

At start, after `Backend started successfully on port 3000`, the backend checks its settings and logs each problem as a `Configuration issue`. It keeps running either way, so read those lines first.

## Start-up

<AccordionGroup>
  <Accordion title="The container restarts in a loop, or gets killed">
    Usually memory. The Compose stack needs about 4 GB. `docker stats` shows usage, and `dmesg` on the host shows the kernel killing a process.
  </Accordion>
  <Accordion title="The backend stops: UPLOAD_DIRECTORY is not set">
    The log says `STORAGE_PROVIDER is "local" but UPLOAD_DIRECTORY is not set`. Local storage needs a folder. In the official image, set `UPLOAD_DIRECTORY=/uploads` and `NEXT_PUBLIC_UPLOAD_STATIC_DIRECTORY=uploads`, as the Compose file does. See [Uploads and storage](/configuration/uploads).
  </Accordion>
  <Accordion title="The database connection is refused">
    Check `DATABASE_URL`. Inside a container, `localhost` is the container itself: use the service name, `postqueen-postgres` in the Compose file. `docker compose logs postqueen-postgres` should show `database system is ready to accept connections`. Outside Compose, the container must be on the same Docker network as the database.
  </Accordion>
  <Accordion title="A port is already in use">
    Another program holds 4007, 7233 or 8080. Stop it, or change the left-hand number of that port in `docker-compose.yaml`. If you move 4007, change the port in `MAIN_URL`, `FRONTEND_URL` and `NEXT_PUBLIC_BACKEND_URL` too.
  </Accordion>
  <Accordion title="Building from source runs out of memory">
    The build needs more memory than running the image. Raise Node's limit for the build, `NODE_OPTIONS="--max-old-space-size=4096" pnpm run build`, but not above the machine's memory. On a small server, pull the published image instead of building.
  </Accordion>
</AccordionGroup>

## Sign-in

<AccordionGroup>
  <Accordion title="Signing in returns to the login page">
    The browser dropped the login cookie. On HTTPS, `FRONTEND_URL` must match the address in the browser exactly, with the scheme and without a trailing slash. On plain HTTP, the cookie needs `NOT_SECURED=true`, which is for a local try only.
  </Accordion>
  <Accordion title="Origin not allowed">
    The backend accepts browser requests only from `FRONTEND_URL` and `MAIN_URL`. Opening PostQueen on any other host or port is refused. Set both to the address people use.
  </Accordion>
  <Accordion title="Everyone was signed out after a restart">
    `JWT_SECRET` changed. It signs every session. If `ENCRYPTION_KEY` was never set, the same value also encrypted the API key and the stored credentials of networks such as Bluesky and WordPress, and those stop working too. **Put the old value back**: that recovers everything. Then set `ENCRYPTION_KEY` to that same value before you rotate `JWT_SECRET`. See [Encryption keys](/configuration/reference#encryption-keys).
  </Accordion>
  <Accordion title="Continue with Google is denied, or only some accounts get in">
    Google sign-in uses the YouTube web client, `YOUTUBE_CLIENT_ID` and `YOUTUBE_CLIENT_SECRET`, and its redirect URI `FRONTEND_URL` + `/integrations/social/youtube`. While the Google app is in **Testing**, only its listed test users can sign in: publish it, or add the person. See [YouTube setup](/installation/providers/youtube).
  </Accordion>
  <Accordion title="Google consent works, then sign-in fails with invalid_client">
    The backend log shows `invalid_client` from Google's token endpoint: `YOUTUBE_CLIENT_SECRET` does not belong to that client. Add a new secret to the same web client in Google Cloud, put it in `.env`, and recreate the container. Google shows a secret in full only when you create it.
  </Accordion>
  <Accordion title="A single sign-on button appears that nobody set up">
    `POSTQUEEN_GENERIC_OAUTH` has a value, often `"false"` copied from `.env.example`. Any value turns it on. Remove the line. See [Single sign-on (OIDC)](/configuration/oauth).
  </Accordion>
  <Accordion title="New accounts stay inactive">
    `REQUIRE_EMAIL_ACTIVATION=true` with a mail provider that cannot deliver. Fix [email](/configuration/emails), or remove the setting.
  </Accordion>
</AccordionGroup>

## Connecting channels

<AccordionGroup>
  <Accordion title="The network's authorization page shows an error">
    The network's keys are missing, wrong, or the redirect URI registered with the network does not match. **Add Channel** lists every network whether or not its keys are set, so the error appears on the network's side. The redirect URI is `FRONTEND_URL` + `/integrations/social/` + the network's ending: [Channel developer apps](/installation/providers/overview) lists them.
  </Accordion>
  <Accordion title="Connecting worked yesterday and fails after a domain change">
    Every redirect URI is built from `FRONTEND_URL`. Update the redirect URI in each network's developer console to the new address.
  </Accordion>
  <Accordion title="fetch failed, with Blocked IP in the log">
    The server refused to call a private or local address. That protects against requests to your internal network. If the Bluesky, Lemmy, WordPress, Listmonk or Mastodon server really is on your network and everyone who can add channels is trusted, set `DISABLE_SSRF_PROTECTION=true`. Otherwise fix DNS so the name resolves to a public address.
  </Accordion>
  <Accordion title="fetch failed without Blocked IP">
    The server cannot reach the network's API: DNS, a firewall or blocked egress. PostQueen reads no `HTTPS_PROXY`, so behind an egress proxy allow the hosts at the network layer. [Self-hosting overview](/installation/overview#outbound-connections) lists the main ones.
  </Accordion>
  <Accordion title="Hide a network from Add Channel">
    Set `HIDDEN_PROVIDERS` to the identifiers to hide, for example `tiktok,x`, and recreate the container. Connected channels keep working. `MIGRATE_PROVIDERS` moves channels to another network on their next reconnect: see [Hide or move a network](/configuration/reference#hide-or-move-a-network).
  </Accordion>
</AccordionGroup>

## Posts and background work

<AccordionGroup>
  <Accordion title="Posts are scheduled and never publish">
    Publishing runs in the orchestrator, through Temporal. Check that the `temporal` container is healthy (`docker compose ps`) and that `TEMPORAL_ADDRESS` points at it. Both the backend and the orchestrator must reach it. Running from source, `pnpm run dev-backend` starts no orchestrator: use `pnpm run dev`.
  </Accordion>
  <Accordion title="Posts that failed to schedule are never picked up">
    `RUN_CRON` is not set, so the recurring recovery workflow never started. Set `RUN_CRON=true` on one backend. The Helm chart does not set it.
  </Accordion>
  <Accordion title="A post failed">
    Open the post in the calendar: the error the network returned is on the post. See [A post did not go out](/troubleshooting/post-failed).
  </Accordion>
</AccordionGroup>

## Uploads and email

<AccordionGroup>
  <Accordion title="Uploaded images do not show">
    With local storage in the official image, `UPLOAD_DIRECTORY` must be `/uploads` and `NEXT_PUBLIC_UPLOAD_STATIC_DIRECTORY` must be `uploads`. After a domain change, old files keep the old address until you set `PREVIOUS_FRONTEND_URLS`. See [Uploads and storage](/configuration/uploads#move-to-a-new-address).
  </Accordion>
  <Accordion title="Posts with media fail on Instagram, Facebook or Threads">
    Those networks download the file from its address. On a laptop or a private network the address is not reachable from the internet. Use a public HTTPS domain or [Cloudflare R2](/configuration/r2).
  </Accordion>
  <Accordion title="413 Request Entity Too Large">
    Your reverse proxy limits the body size. Allow 1 GB: `client_max_body_size 1G;` in Nginx. See [Nginx](/reverse-proxies/nginx).
  </Accordion>
  <Accordion title="No email arrives">
    `EMAIL_PROVIDER` must be exactly `resend` or `nodemailer`, with `EMAIL_FROM_ADDRESS` and `EMAIL_FROM_NAME` set. Without them nothing is sent and nothing fails. See [Email](/configuration/emails).
  </Accordion>
</AccordionGroup>

## Platform questions

<AccordionGroup>
  <Accordion title="Can I run it on Vercel or another serverless host?">
    Not the backend or the orchestrator. The backend is a long-running server, and the orchestrator is a Temporal worker that runs all the time. Run them on a virtual machine, a container host or Kubernetes. The official image already runs nginx, the frontend, the backend and the orchestrator together.
  </Accordion>
  <Accordion title="Can I run more than one container?">
    Yes, with shared PostgreSQL, Redis and Temporal. Media needs a volume every container mounts, or [Cloudflare R2](/configuration/r2). Set `RUN_CRON` on one of them only.
  </Accordion>
</AccordionGroup>

Still stuck? [Report it](https://github.com/GkhanKINAY/postqueen-app/issues) with the version, the symptom and the relevant log lines, without keys or secrets.
