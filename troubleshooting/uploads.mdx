## Body size limit

The **50 MB** JSON body limit is mounted on two path prefixes, `/posts` and
`/copilot/*`, which are the internal routes the web UI uses.

`POST /public/v1/posts` is **not** one of them. It falls back to the framework
default of roughly 100 kB, which is far smaller than most people expect and is
reached by a single inlined image. Upload your media first and reference the
returned `path`.

## Accepted MIME types (Public API)

`/public/v1/upload` validates the uploaded file's detected MIME type against
this allowlist:

| Type | MIME |
|---|---|
| JPEG | `image/jpeg` |
| PNG | `image/png` |
| GIF | `image/gif` |
| WebP | `image/webp` |
| AVIF | `image/avif` |
| BMP | `image/bmp` |
| TIFF | `image/tiff` |
| MP4 video | `video/mp4` |

`/public/v1/upload-from-url` applies the same allowlist to the bytes it
downloads, but only after a check on the URL itself: the path, ignoring any
query string, has to end in `.png`, `.jpg`, `.jpeg`, `.gif`, `.webp` or `.mp4`.
AVIF, BMP and TIFF therefore cannot be fetched from a URL at all, only sent
through the multipart endpoint. The refusal is a `400` naming extensions rather
than MIME types, which is the clue that you have hit this check and not the one
above.

Per-file size caps apply to both: **10 MB** for images and **1 GB** for video,
reported as `File size exceeds the maximum allowed size of ... bytes.`

PDFs are **not** accepted by the public API. The only PDF flow PostQueen
supports is LinkedIn document carousels, which are produced internally
by converting an image carousel to PDF. You cannot post a PDF directly
through the public API.

## "PayloadTooLargeError" when creating a post

You sent a request body larger than 50 MB to `POST /public/v1/posts`,
almost always because you inlined image data instead of uploading first.

**Fix:** upload media via `/public/v1/upload` (or `/public/v1/upload-from-url`),
then reference the returned `id` and `path` in the post body's
`image` array.

```bash
# Step 1: upload the file
curl -X POST "https://api.postqueen.ai/public/v1/upload" \
  -H "Authorization: your-api-key" \
  -F "file=@photo.jpg"

# Step 2: pass id + path into the post
```

## `upload-from-url` timeouts or "fetch failed"

`/upload-from-url` proxies the source URL through the PostQueen backend.
If the source server is slow, unreachable, blocks PostQueen's user agent,
or sits behind authentication, the upload fails.

**Fix**

- Make sure the source URL is publicly reachable HTTPS, with no auth.
- Do not link to private S3 URLs, signed URLs that have expired, or
  intranet hosts.
- If the source is consistently slow, pre-download the file locally and
  use the multipart `/upload` endpoint instead.

## "Failed to load video metadata"

PostQueen inspects uploaded videos for duration, dimensions, and codec
before passing them to the social provider. Files outside the supported
range fail here.

**Recommended video format**

- Container: MP4
- Video codec: H.264 (baseline or main profile)
- Audio codec: AAC
- Frame rate: 30 fps or less
- Resolution: ≤ 1920×1080 for most providers; TikTok and YouTube
  Shorts prefer portrait 1080×1920.

Other formats may upload but get rejected by the social provider
downstream.

## "uploader plugin does not allow removing files during an upload"

You hit Cancel on a file that was already being uploaded. PostQueen's
uploader does not support mid-flight cancellation. Wait for the upload
to complete, then delete the asset from the post.

This is a known UX limitation, tracked in [Known Issues](/troubleshooting/known-issues).
