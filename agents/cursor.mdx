Cursor is an AI code editor with a built-in agent. Add PostQueen to its MCP settings and the agent can write posts about what you shipped, schedule them and report how your published posts did, without leaving the editor.

## Before you start

- **Plans:** Cursor lists MCP on its paid Individual plan. For the free Hobby plan, check [cursor.com/pricing](https://cursor.com/pricing).
- **Platforms:** macOS, Windows and Linux.
- **A PostQueen API key.** A workspace admin copies it, or the ready-made address, from **Connections**.

<ApiKeyLocation />

## Connect Cursor

<Steps>
  <Step title="Open mcp.json">
    Open `~/.cursor/mcp.json` to use PostQueen in every project, or `.cursor/mcp.json` in a project to keep it to that one. In the app, MCP servers are under **Customize > MCPs**.
  </Step>
  <Step title="Add PostQueen">
    Add the `postqueen` entry, with your key in place of `YOUR_API_KEY`, and save:

    ```json ~/.cursor/mcp.json
    {
      "mcpServers": {
        "postqueen": {
          "url": "https://api.postqueen.ai/mcp/YOUR_API_KEY"
        }
      }
    }
    ```
  </Step>
  <Step title="Check it in Cursor">
    Open **Customize > MCPs** and check that PostQueen is listed and on.
  </Step>
</Steps>

## Check that it works

Ask Cursor's agent: "List my PostQueen channels." It calls PostQueen and answers with the channels you connected.

## Good to know

- **The file holds your key** when you use the key address. Keep `.cursor/mcp.json` out of version control, or use the header form below.
- **Cursor's agent can add the entry for you** if you allow it to edit `mcp.json`.
- **Grok Bot runs on Cursor's cloud,** but it does not read Cursor's `mcp.json`. It has [its own setup](/agents/grok-bot).
- **Ask for drafts when you want to check first.** A draft waits on your PostQueen calendar, and nothing publishes until you schedule it.
- **What it cannot do over MCP:** delete a post, or change a post's text or time. Do that on the calendar in the app. [The MCP tools](/mcp/tools) lists what it can do.

## Other ways to connect

| Way | Address | Status |
|---|---|---|
| The key in the address | `{{mcpKeyUrl}}` | From Cursor's docs. The route above |
| The Bearer header, key read from your environment | `{{mcpBearerUrl}}` | From Cursor's docs |

<Tabs>
  <Tab title="Bearer header">
    Cursor fills in `${env:NAME}` from your environment, so the key stays out of the file:

    ```json ~/.cursor/mcp.json
    {
      "mcpServers": {
        "postqueen": {
          "url": "https://api.postqueen.ai/mcp",
          "headers": {
            "Authorization": "Bearer ${env:POSTQUEEN_API_KEY}"
          }
        }
      }
    }
    ```
  </Tab>
  <Tab title="Sign in (not tested yet)">
    Set `"url"` to `https://api.postqueen.ai/mcp-oauth-dynamic`, with no headers. Cursor registers itself and opens the PostQueen sign-in, which a workspace admin approves. In the Cursor CLI, run `agent mcp login postqueen`.

    The sign-in address has {{mcpToolsOauth}} tools, all but `ask_postqueen`. Revoke access in PostQueen under **Connections > Approved Apps**.
  </Tab>
</Tabs>

## Try this first

```text wrap
We just shipped dark mode. List my PostQueen channels, then write a short Bluesky post about it and save it as a draft for tomorrow at 9am.
```

The draft appears on your PostQueen calendar, ready for you to check and schedule. [Prompts to try](/mcp/examples) has more.

## Troubleshooting

| Symptom | Fix |
|---|---|
| The agent does not list PostQueen | Check that the `postqueen` entry is in `~/.cursor/mcp.json` or `.cursor/mcp.json`, and look under **Customize > MCPs**. |
| It works in one project only | `.cursor/mcp.json` covers one project. Use `~/.cursor/mcp.json` for all of them. |
| The Cursor CLI does not sign in | Run `agent mcp login postqueen`. |
| The key is refused | Copy it again from **Connections > API Keys**. Only a workspace Admin or Super Admin can reveal it. |

More fixes are on [Troubleshooting agents](/agents/troubleshooting).
