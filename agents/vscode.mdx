VS Code is Microsoft's code editor, and GitHub Copilot's agent sessions in it use MCP servers. Add PostQueen once and Copilot can write posts about your work for PostQueen to schedule, and report how your published posts did.

## Before you start

- **Plans:** you need GitHub Copilot. Copilot Free, Pro, Pro+ and Max are not restricted. On Copilot Business and Enterprise, your organization's **MCP servers in Copilot** policy must allow it.
- **Platforms:** VS Code 1.140 or later on macOS, Windows and Linux.
- **A PostQueen API key.** A workspace admin copies it, or the ready-made address, from **Connections**.

## Connect VS Code

<Steps>
  <Step title="Add the server">
    Open the Command Palette and run **MCP: Add Server**. Choose **HTTP (HTTP or Server-Sent Events)** and paste your key address:

    ```text wrap
    https://api.postqueen.ai/mcp/YOUR_API_KEY
    ```

    Enter `postqueen` as the server ID, then choose **Global**, then **Copilot Global**. VS Code writes the server to `~/.copilot/mcp-config.json`.
  </Step>
  <Step title="Start it">
    VS Code might ask you to confirm that you trust the server. If it does, confirm, then open the Copilot chat.
  </Step>
</Steps>

<Accordion title="Prefer to edit the file yourself?" icon="file-code">
  **Copilot Global** is `~/.copilot/mcp-config.json`, which uses `mcpServers`:

  ```json ~/.copilot/mcp-config.json
  {
    "mcpServers": {
      "postqueen": {
        "type": "http",
        "url": "https://api.postqueen.ai/mcp/YOUR_API_KEY"
      }
    }
  }
  ```

  A project's `.vscode/mcp.json` still works too, for compatibility. It uses `servers`:

  ```json .vscode/mcp.json
  {
    "servers": {
      "postqueen": {
        "type": "http",
        "url": "https://api.postqueen.ai/mcp/YOUR_API_KEY"
      }
    }
  }
  ```
</Accordion>

## Check that it works

In the Copilot chat, ask: "List my PostQueen channels." Copilot calls PostQueen and answers with the channels you connected.

## Good to know

- **Two file shapes.** `~/.copilot/mcp-config.json` uses `"mcpServers"`, and a project's `.vscode/mcp.json` uses `"servers"`. Both need `"type": "http"`.
- **The file holds your key** when you use the key address. Keep a project's `.vscode/mcp.json` out of version control, or, in a Local session, use an input variable below.
- **Copilot can add the entry for you** in the Copilot chat, if you allow it to edit the file.
- **Ask for drafts when you want to check first.** A draft waits on your PostQueen calendar, and nothing publishes until you schedule it.
- **What it cannot do over MCP:** delete a post, or change a post's text or time. Do that on the calendar in the app. [The MCP tools](/mcp/tools) lists what it can do.

## Other ways to connect

| Way | Address | Notes |
|---|---|---|
| The key in the address | `{{mcpKeyUrl}}` | From Microsoft's docs. The route above |
| The Bearer header from an input variable | `{{mcpBearerUrl}}` | From Microsoft's docs |
| Sign in with PostQueen | `{{mcpOauthUrl}}` | A workspace admin approves the sign-in |

<Tabs>
  <Tab title="Input variable (Local sessions)">
    An input variable makes VS Code prompt you for the key instead of reading it from the file, so the file holds no secret. Input variables work only in **Local** harness sessions:

    ```json .vscode/mcp.json
    {
      "inputs": [
        {
          "type": "promptString",
          "id": "postqueen-key",
          "description": "PostQueen API key",
          "password": true
        }
      ],
      "servers": {
        "postqueen": {
          "type": "http",
          "url": "https://api.postqueen.ai/mcp",
          "headers": {
            "Authorization": "Bearer ${input:postqueen-key}"
          }
        }
      }
    }
    ```
  </Tab>
  <Tab title="Sign in">
    Use `https://api.postqueen.ai/mcp-oauth-dynamic` as the URL, with no headers. VS Code registers itself and opens the PostQueen sign-in, which a workspace admin approves.

    The sign-in address has {{mcpToolsOauth}} tools, all but `ask_postqueen`. Revoke access in PostQueen under **Connections > Approved Apps**.
  </Tab>
</Tabs>

## Try this first

```text wrap
List my PostQueen channels. Then write a short Bluesky post about the feature in this branch and save it as a draft for tomorrow at 9am.
```

The draft appears on your PostQueen calendar, ready for you to check and schedule. [Prompts to try](/mcp/examples) has more.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Copilot does not list PostQueen | Run **MCP: List Servers** and check that PostQueen is running, then ask in the Copilot chat. |
| The server does not start | Check the shape: `"mcpServers"` in `~/.copilot/mcp-config.json`, `"servers"` in `.vscode/mcp.json`, and `"type": "http"` in both. |
| On Business or Enterprise, MCP is not available | Your organization's **MCP servers in Copilot** policy must allow it. Ask your GitHub admin. |
| The key is refused | Copy it again from **Connections > API key**. Only a workspace Admin or Super Admin can reveal it. |

More fixes are on [Troubleshooting agents](/agents/troubleshooting).
