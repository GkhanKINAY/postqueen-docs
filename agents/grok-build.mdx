Grok Build is xAI's coding agent for the terminal: the `grok` CLI. It also runs headless in scripts and inside other apps, and its source is open under Apache 2.0. Add PostQueen with one command and Grok Build can announce a release, draft posts from your repo and report how published posts did, without leaving the terminal.

## Before you start

- **Plans:** xAI first opened the `grok` CLI to SuperGrok and X Premium+ subscribers. No xAI plan page names the CLI today; free and X Basic accounts get a usage limit. Sign in through the browser, with `grok login --device-auth`, or with an xAI API key.
- **Platforms:** the terminal on macOS, Linux and Windows. WSL uses the Linux build.
- **A PostQueen API key.** A workspace admin copies it, or the ready-made address, from **Connections**.

## Connect Grok Build

<Steps>
  <Step title="Add PostQueen">
    Run this in your terminal, with your key in place of `YOUR_API_KEY`:

    ```bash
    grok mcp add --transport http postqueen \
      https://api.postqueen.ai/mcp/YOUR_API_KEY
    ```

    It saves PostQueen in your user config, `~/.grok/config.toml`, so every project can use it.
  </Step>
  <Step title="Check the server">
    Run the doctor, or type `/mcps` inside Grok Build to open the extensions modal:

    ```bash
    grok mcp doctor postqueen
    ```
  </Step>
</Steps>

## Check that it works

Start Grok Build and ask: "List my PostQueen channels." It calls PostQueen and answers with the channels you connected. If PostQueen is missing, run `grok mcp list` to see whether the server is saved.

## Good to know

- **Keep the key out of the file** with the header form under [Other ways to connect](#other-ways-to-connect). The command above writes the key into `config.toml`.
- **One project only:** add `--scope project` to write `.grok/config.toml` in the project instead of your user config.
- **Grok Build also reads** `~/.claude.json`, `.cursor/mcp.json` and a project `.mcp.json`, at a lower priority than its own config. A server you already added for Claude Code or Cursor can show up here too.
- **Ask for drafts when you want to check first.** A draft waits on your PostQueen calendar, and nothing publishes until you schedule it.
- **What it cannot do over MCP:** delete a post, or change a post's text or time. Do that on the calendar in the app. [The MCP tools](/mcp/tools) lists what it can do.

| Way | Address | Status |
|---|---|---|
| The key in the address | `{{mcpKeyUrl}}` | From xAI's docs. The route above |

<Tabs>
  <Tab title="Bearer header">
    Grok reads `${POSTQUEEN_API_KEY}` from your environment when it loads, so the key stays out of `config.toml`:

    ```bash
    export POSTQUEEN_API_KEY=YOUR_API_KEY
    grok mcp add --transport http postqueen https://api.postqueen.ai/mcp \
      --header 'Authorization: Bearer ${POSTQUEEN_API_KEY}'
    ```

    Keep the single quotes. With double quotes your shell writes the key itself into `config.toml`.
  </Tab>
  <Tab title="Sign in (not tested yet)">
    Add the sign-in address, then sign in from the extensions modal. It has {{mcpToolsOauth}} tools, all but `ask_postqueen`.

    ```bash
    grok mcp add --transport http postqueen \
      https://api.postqueen.ai/mcp-oauth-dynamic
    ```

    Type `/mcps` in Grok Build, select PostQueen and press `i` to sign in. A workspace admin signs in to PostQueen and approves. Grok keeps the token on your computer, and you can revoke it in PostQueen under **Connections > Approved Apps**.
  </Tab>
  <Tab title="Plugin (not tested yet)">
    The postqueen skill drives the [PostQueen CLI](/cli/introduction), so install the CLI and set your key first:

    ```bash
    npm install -g postqueen
    export POSTQUEEN_API_KEY=YOUR_API_KEY
    grok plugin marketplace add GkhanKINAY/postqueen-agent
    grok plugin install postqueen --trust
    ```

    See [the postqueen skill](/agents/skill) for what it teaches an agent.
  </Tab>
</Tabs>

## Troubleshooting

| Symptom | Fix |
|---|---|
| PostQueen tools do not show up | Run `grok mcp doctor postqueen`, or open `/mcps` and check the server. |
| Your key ended up in `config.toml` | Add the server again with the header in single quotes, so Grok reads `${POSTQUEEN_API_KEY}` from your environment. |
| The key is refused | Copy it again from **Connections > API Keys**. Only a workspace Admin or Super Admin can reveal it. |
| PostQueen works in one project only | It was added with `--scope project`. Add it again without the flag for your user config. |
| You set up Grok or Grok Bot instead | Each product is set up on its own. Open its page below. |

More fixes are on [Troubleshooting agents](/agents/troubleshooting).

## Is it the same as Grok or Grok Bot?

No. xAI has three products with Grok in the name, and each one connects to PostQueen on its own:

| Product | What it is | How it connects |
|---|---|---|
| **Grok Build** (this page) | xAI's coding agent for the terminal | One `grok mcp add` command |
| [Grok](/agents/grok) | xAI's assistant at grok.com and in its mobile apps | A custom connector at grok.com/connectors |
| [Grok Bot](/agents/grok-bot) | An always-on AI teammate with its own cloud computer | Ask in chat, key in the secure prompt |

A server in Grok Build's `config.toml` does not reach Grok on grok.com or Grok Bot.
