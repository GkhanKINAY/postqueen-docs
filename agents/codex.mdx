Codex is OpenAI's coding agent, available as a CLI, an IDE extension, in the ChatGPT desktop app and in the cloud. Add PostQueen once and Codex can write posts from your commits, schedule them and report how your published posts did.

## Before you start

- **Plans:** every ChatGPT plan includes Codex: Free and Go (in the desktop app, as it rolls out), Plus, Pro, Business, Enterprise and Edu. Weekly limits may apply.
- **Platforms:** the CLI, the IDE extension and the ChatGPT desktop app, which share one config, plus Codex on the web.
- **A PostQueen API key.** A workspace admin copies it, or the ready-made address, from **Connections**.

## Connect Codex

<Steps>
  <Step title="Add PostQueen">
    Run this in your terminal, with your key in place of `YOUR_API_KEY`:

    ```bash
    codex mcp add postqueen \
      --url https://api.postqueen.ai/mcp/YOUR_API_KEY
    ```

    Codex saves it in `~/.codex/config.toml`, which the CLI, the IDE extension and the ChatGPT desktop app all read.
  </Step>
  <Step title="Check the server">
    Run `codex mcp list`, or type `/mcp` inside Codex.
  </Step>
  <Step title="Restart the app you use">
    In the IDE extension, choose **Restart extension**. In the ChatGPT desktop app, restart it. In the CLI, start a new session.
  </Step>
</Steps>

<Tip>
**Prefer a form?** In the IDE extension, open the gear menu, then **MCP servers > Add server > Streamable HTTP**, paste the address, save and choose **Restart extension**. In the ChatGPT desktop app, open **Settings > MCP servers > Add server**, then restart.
</Tip>

## Check that it works

Ask Codex: "List my PostQueen channels." It calls PostQueen and answers with the channels you connected.

## Good to know

- **Use MCP rather than the PostQueen CLI in Codex.** The default workspace-write sandbox has network access off, so every CLI call asks for approval and unattended runs fail.
- **Codex will not connect PostQueen on its own.** It offers to guide you and asks for the address; the reliable step is the `codex mcp add` command.
- **For one project only,** put the server in `.codex/config.toml` inside a trusted project. Codex reads that file too.
- **ChatGPT on the web does not read this config.** Add PostQueen to ChatGPT on its own; see [ChatGPT](/agents/chatgpt).
- **Ask for drafts when you want to check first.** A draft waits on your PostQueen calendar, and nothing publishes until you schedule it.
- **What it cannot do over MCP:** delete a post, or change a post's text or time. Do that on the calendar in the app. [The MCP tools](/mcp/tools) lists what it can do.

## Other ways to connect

| Way | Address | Notes |
|---|---|---|
| The key in the address | `{{mcpKeyUrl}}` | From OpenAI's docs. The route above |
| The Bearer token, read from your environment | `{{mcpBearerUrl}}` | From OpenAI's docs |
| Sign in with PostQueen | `{{mcpOauthUrl}}` | A workspace admin approves the sign-in |

<Tabs>
  <Tab title="Bearer token">
    Codex reads the key from `POSTQUEEN_API_KEY` when it starts, so it stays out of `config.toml`:

    ```bash
    export POSTQUEEN_API_KEY=YOUR_API_KEY
    codex mcp add postqueen --url https://api.postqueen.ai/mcp \
      --bearer-token-env-var POSTQUEEN_API_KEY
    ```

    `codex mcp add` has no header flag. Other headers go under `http_headers` in `config.toml`.
  </Tab>
  <Tab title="Sign in">
    ```bash
    codex mcp add postqueen \
      --url https://api.postqueen.ai/mcp-oauth-dynamic
    ```

    Codex detects the sign-in and opens the PostQueen sign-in page, which a workspace admin approves. `codex mcp login postqueen` runs it again. The sign-in address has {{mcpToolsOauth}} tools, all but `ask_postqueen`. Revoke access in PostQueen under **Connections > Approved Apps**.
  </Tab>
</Tabs>

## Try this first

```text wrap
Read the last ten commits and write one short Bluesky post about what changed. Save it in PostQueen as a draft for Monday at 10am.
```

The draft appears on your PostQueen calendar, ready for you to check and schedule. [Prompts to try](/mcp/examples) has more.

## Run it on a schedule

`codex exec` runs Codex without a chat, from cron or a CI job. It reads the same `config.toml`, so the PostQueen tools come along:

```bash
codex exec "Turn the last ten commits into three PostQueen drafts for Bluesky"
```

Source: [OpenAI, non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode).

## Troubleshooting

| Symptom | Fix |
|---|---|
| Every PostQueen CLI call asks for approval | The default sandbox has network access off. Use the MCP server instead of the CLI. |
| The IDE extension does not see PostQueen | Choose **Restart extension** after you add the server. |
| ChatGPT on the web does not see it | It does not read Codex's config. Add PostQueen to ChatGPT on its own. |
| The key is refused | Copy it again from **Connections > API Keys**. Only a workspace Admin or Super Admin can reveal it. |

More fixes are on [Troubleshooting agents](/agents/troubleshooting).

## Is it the same as ChatGPT?

No. Codex lives in the ChatGPT desktop app, but ChatGPT on the web has its own setup:

| Product | What it is | How it connects |
|---|---|---|
| **Codex** (this page) | OpenAI's coding agent: CLI, IDE extension and the ChatGPT desktop app | One `codex mcp add` command |
| [ChatGPT](/agents/chatgpt) | OpenAI's assistant on the web | A developer mode app at chatgpt.com/plugins |

The **MCP servers** setting in the ChatGPT desktop app belongs to Codex, not to the web chat.
