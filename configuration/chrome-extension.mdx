Skool has no public API, so PostQueen connects it through the PostQueen browser extension. The extension reads the Skool session cookies from your own Chrome and hands them to your instance. It only answers pages on the domain it was built for, so on a self-hosted PostQueen you build it with your instance's address, load it into Chrome, and tell PostQueen its ID.

Skool is the only channel that uses the extension today.

## Before you start

| | |
|---|---|
| Browser | Chrome, or another Chromium browser, signed in to [skool.com](https://www.skool.com) |
| Source | The [app repository](https://github.com/GkhanKINAY/postqueen-app), with Node.js 22 and pnpm |
| Build variables | `FRONTEND_URL` and `NEXT_PUBLIC_BACKEND_URL`, the same values your instance runs with |
| Instance variables | `EXTENSION_ID`, and `EXTENSION_STORE_URL` if you publish the extension |
| Your address | Served over `https` on the default port. `localhost` works on any port |
| Review | None for an unpacked build. A Chrome Web Store item goes through the store's review |

<Warning>
Using a browser extension to interact with a platform may violate its terms of service and could result in your account being suspended or banned. PostQueen shows the same notice before a Skool account connects.
</Warning>

## How it works

1. The Chrome build writes your domain and its subdomains into the extension twice: into the manifest's `externally_connectable` list, which decides which pages can reach the extension at all, and into the extension's own check of every message's origin. It also grants the extension access to your frontend and backend addresses.
2. When someone picks **Skool** in **Add Channel**, PostQueen shows a **Browser Extension Notice**. After **I understand, continue**, the page asks the extension with the ID in `EXTENSION_ID` for the `client_id` and `auth_token` cookies of skool.com, and PostQueen stores them encrypted.
3. From then on the extension sends fresh cookies to your backend once a day, whenever Chrome is running, so the connection stays alive.

## Build the extension

<Steps>
  <Step title="Get the source">
    Clone the app repository and install the workspace at its root. The extension has no dependencies of its own, so the root install is what it builds with:

    ```bash
    git clone https://github.com/GkhanKINAY/postqueen-app
    cd postqueen-app
    pnpm install
    ```
  </Step>
  <Step title="Build it for your domain">
    Build with the Chrome configuration, passing your instance's two addresses:

    ```bash
    cd apps/extension
    FRONTEND_URL="https://postqueen.example.com" \
    NEXT_PUBLIC_BACKEND_URL="https://postqueen.example.com/api" \
    pnpm exec vite build --config vite.config.chrome.ts
    ```

    The build goes to `apps/extension/dist`. Its `manifest.json` lists `https://postqueen.example.com/*` and `https://*.postqueen.example.com/*` under `externally_connectable`. Nothing in the source needs editing.

    <Warning>
    **Not `pnpm build`.** That script packs the extension the way the published build is packed: it copies `manifest.json` unchanged and does not read `FRONTEND_URL`, so the result answers only pages on `localhost`, never your domain.
    </Warning>
  </Step>
  <Step title="Load it into Chrome">
    Open `chrome://extensions`, turn on **Developer mode**, choose **Load unpacked** and pick the `apps/extension/dist` folder.
  </Step>
  <Step title="Copy the extension ID">
    Chrome shows the ID under the extension's name, a string of 32 letters. An unpacked extension's ID comes from the folder it was loaded from: loading the same folder again keeps it, and loading a copy from another folder or another computer gives a new one.
  </Step>
</Steps>

## Set the variables

Add the ID to your environment:

```env
EXTENSION_ID="the 32-letter id Chrome shows"
# Optional: your own Web Store listing
EXTENSION_STORE_URL="https://chromewebstore.google.com/detail/your-listing"
```

`EXTENSION_ID` is one value for the whole instance, so every browser that connects Skool needs the build with that ID:

| Who connects Skool | What to do | `EXTENSION_ID` |
|---|---|---|
| One browser | Load the build unpacked, as above | The ID Chrome shows for it |
| Several people | Zip the contents of `dist`, publish it on the Chrome Web Store (an unlisted item is enough), and set `EXTENSION_STORE_URL` to its page | The ID the Web Store gives the item |

<Tip>
To give unpacked copies on different computers the same ID without publishing, upload the zipped build to the Chrome Web Store developer dashboard without publishing it, copy the public key it shows, and add it as `"key"` to `apps/extension/manifest.json` before you build. See Chrome's guide to the [manifest key](https://developer.chrome.com/docs/extensions/reference/manifest/key).
</Tip>

Then open **Channels**, choose **Add Channel**, then **Skool**, and continue past the notice. The account appears in the **Channels** list.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Extension Not Found">
    The window says "The PostQueen browser extension is not installed. You need to install it before connecting this channel." Either `EXTENSION_ID` is empty on the instance, or no enabled extension in this browser trusts the page: the build is not loaded, it is turned off, it was built for another domain or with `pnpm build`, or PostQueen is open over plain `http` on an address other than `localhost`.
  </Accordion>
  <Accordion title="PostQueen browser extension is not installed or not reachable.">
    The page can reach an extension but not this one. `EXTENSION_ID` is not the ID Chrome shows for the loaded build, or the build's origin check refused the page because it was built with another `FRONTEND_URL` or PostQueen runs on a port other than 443. Fix the ID or rebuild, then recreate the container.
  </Accordion>
  <Accordion title="Missing required cookies: client_id, auth_token">
    The browser is not signed in to Skool. Sign in at skool.com in the same Chrome profile, then connect again.
  </Accordion>
  <Accordion title="Failed to communicate with the browser extension.">
    The extension stopped answering mid-connect. Reload it on `chrome://extensions`, reload PostQueen and try again.
  </Accordion>
  <Accordion title="The Skool channel disconnects after a while">
    The daily cookie refresh only runs while Chrome is open with the extension, and the extension can only reach the backend address it was built with. Keep Chrome running, rebuild if `NEXT_PUBLIC_BACKEND_URL` changed, and reconnect the channel.
  </Accordion>
</AccordionGroup>
