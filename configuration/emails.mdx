A self-hosted PostQueen sends no mail until you give it a provider. Without one, password resets report success and send nothing, so a person locked out has no way back in. Set this up before you invite anyone.

PostQueen sends password reset links, invitations, one-time sign-in codes when [passwordless sign-in](/configuration/rate-limits#passwordless-sign-in) is on, activation links when activation is on, and the notification emails each person chooses in **Settings > Notifications**.

## Set up a provider

<Steps>
  <Step title="Choose the provider and the sender">
    `EMAIL_PROVIDER` must be exactly `resend` or `nodemailer`. Any other value, including a typo or no value, selects a provider that sends nothing and reports no error. Both need a sender:

    ```env
    EMAIL_FROM_NAME=PostQueen
    EMAIL_FROM_ADDRESS=hello@example.com
    ```

    Without both sender values no mail goes out, even with a provider.
  </Step>
  <Step title="Add the credentials">
    <Tabs>
      <Tab title="Resend">
        Create an account at [Resend](https://resend.com), verify the domain you send from, and create an API key.

        ```env
        EMAIL_PROVIDER=resend
        RESEND_API_KEY=re_your_key
        EMAIL_FROM_NAME=PostQueen
        EMAIL_FROM_ADDRESS=hello@example.com
        ```

        `EMAIL_FROM_ADDRESS` has to be on the domain you verified, or Resend refuses the mail.
      </Tab>
      <Tab title="SMTP">
        `nodemailer` sends through any SMTP server:

        ```env
        EMAIL_PROVIDER=nodemailer
        EMAIL_HOST=smtp.example.com
        EMAIL_PORT=465
        EMAIL_SECURE=true
        EMAIL_USER=your-smtp-user
        EMAIL_PASS=your-smtp-password
        EMAIL_FROM_NAME=PostQueen
        EMAIL_FROM_ADDRESS=hello@example.com
        ```

        `EMAIL_SECURE=true` goes with port 465, which is encrypted from the first byte. For port 587 with STARTTLS, set `EMAIL_SECURE=false`.
      </Tab>
    </Tabs>
  </Step>
  <Step title="Recreate the container">
    <RestartService />

    The backend logs the provider it picked, and any credential it misses:

    ```bash
    docker compose logs postqueen | grep -iE "email service provider|missing environment variable"
    ```

    <Check>
    `Email service provider: resend` (or `nodemailer`), with no `Missing environment variable` line after it.
    </Check>
  </Step>
  <Step title="Send a test">
    Use **Forgot password?** on the login page with an address you can read. The mail should arrive within a minute.
  </Step>
</Steps>

Mail goes out through a Temporal workflow that the orchestrator runs, so a stack without a working Temporal sends nothing either.

## Require activation for new accounts

By default a new email-and-password account can sign in at once. To make people confirm their address first:

```env
REQUIRE_EMAIL_ACTIVATION=true
```

Activation then applies once mail can actually go out: a provider named in `EMAIL_PROVIDER` and both sender values. Sign-ups through Google, Apple, GitHub or your own single sign-on skip it, because the provider already vouched for the address.

<Warning>
**Finish the provider before you turn activation on.** With a provider named but its credentials wrong or missing, for example `EMAIL_PROVIDER=resend` without `RESEND_API_KEY`, every new account is created inactive and its activation mail never arrives.
</Warning>

## If mail does not arrive

<AccordionGroup>
  <Accordion title="Nothing is sent and nothing is logged">
    `EMAIL_PROVIDER` is not exactly `resend` or `nodemailer`, or one of the two sender values is missing. The log line `Email service provider:` shows which provider was chosen; `no provider` means none.
  </Accordion>
  <Accordion title="Resend refuses the mail">
    `EMAIL_FROM_ADDRESS` is not on a domain verified in your Resend account.
  </Accordion>
  <Accordion title="SMTP times out">
    Many hosting providers block outbound mail ports until you ask. Test from the server: `nc -zv smtp.example.com 465`.
  </Accordion>
  <Accordion title="New accounts stay inactive">
    Activation is on and the mail is not getting out. Fix the provider, then have the person request a new activation mail from the login page.
  </Accordion>
</AccordionGroup>
