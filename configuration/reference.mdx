PostQueen reads all of its settings from environment variables. With Docker Compose they go in the `.env` file next to `docker-compose.yaml`: see [Docker Compose](/installation/docker-compose#where-settings-live). A change takes effect when the `postqueen` container is recreated, not restarted:

```bash
docker compose up -d --no-deps --force-recreate postqueen
```

- **`NEXT_PUBLIC_` variables need no rebuild.** The web app renders its pages on the server and hands these values to the browser at run time, so recreating the container is enough. The one exception is `NEXT_PUBLIC_APP_VERSION`, which is fixed when the image is built.
- **The start-up check only warns.** After the backend is listening it checks the required values below and logs each problem as a `Configuration issue`. Nothing stops, so a running container is not proof that the settings are right: `docker compose logs postqueen | grep -i "configuration issue"`.
- **The backend and the orchestrator read the same variables.** In the official image both run in one container. If you run them apart, give both the same environment.

## Required

The start-up check reports these when they are missing, and URLs when they are not valid or end in `/`.

| Variable | What it is |
|---|---|
| `DATABASE_URL` | PostgreSQL connection string, for example `postgresql://user:password@postqueen-postgres:5432/postqueen-db-local`. |
| `REDIS_URL` | Redis connection string, starting with `redis://`. Holds caches, rate-limit counters and short-lived sign-in state. The schedule lives in Temporal, not Redis. |
| `JWT_SECRET` | A long random string that signs login sessions. Changing it signs everyone out. Unless `ENCRYPTION_KEY` is set it also encrypts stored secrets: see [Encryption keys](#encryption-keys). |
| `FRONTEND_URL` | The address people open in the browser, for example `https://postqueen.example.com`. Every network's redirect address, email links and the allowed browser origin are built from it. |
| `NEXT_PUBLIC_BACKEND_URL` | The address the browser uses for the API. With the official image it is `FRONTEND_URL` + `/api`. With a backend on its own host, that host with no path. |
| `BACKEND_INTERNAL_URL` | How the web app's server reaches the API. `http://localhost:3000` in the official image, whatever your domain. In a [split deployment](/reverse-proxies/split-deployments), the backend's internal address. |
| `MAIN_URL` | Added to the allowed browser origins next to `FRONTEND_URL`. Set it to the same address. |
| `STORAGE_PROVIDER` | `local` or `cloudflare`. See [Storage and media](#storage-and-media). |

## Encryption keys

| Variable | What it is |
|---|---|
| `ENCRYPTION_KEY` | Encrypts the secrets PostQueen stores: the workspace API key, OAuth app client secrets, the passwords and keys typed in to connect networks such as Bluesky, WordPress and Nostr, and the Skool cookies. Unset, `JWT_SECRET` is used. |
| `PREVIOUS_ENCRYPTION_KEY` | The key the data was encrypted with before the current one. Decryption tries `ENCRYPTION_KEY` first, then this. |

A channel's OAuth access and refresh tokens, the ones a network hands back after sign-in, are stored as the network returned them and are not encrypted with this key. Treat a database dump as sensitive.

- **On a new install**, set `ENCRYPTION_KEY` to its own random value before there is data. `JWT_SECRET` then only signs sessions, and rotating it only signs people out.
- **On an install that never set it**, set `ENCRYPTION_KEY` to the current value of `JWT_SECRET`. Nothing needs re-encrypting, because that is the key already in use. After that you can rotate `JWT_SECRET` freely.
- **To rotate `ENCRYPTION_KEY`**, copy the current value into `PREVIOUS_ENCRYPTION_KEY`, put the new value in `ENCRYPTION_KEY`, and recreate the container. Leave both set: a row is re-encrypted only when something rewrites it, so data nobody touches stays on the old key.

## How switches are read

<Warning>
**For most switches, `false` means on.** Only these compare against the exact string `true`: `DISABLE_REGISTRATION`, `PASSWORDLESS_LOGIN`, `WALLET_LOGIN`, `REQUIRE_EMAIL_ACTIVATION`, `NOT_SECURED`, `DISABLE_SSRF_PROTECTION`, `TEMPORAL_TLS`, `EMAIL_SECURE`, `UPLOAD_VIA_SERVER` and `NEYNAR_SPONSOR_SIGNERS`. Every other switch on this page is on when it has any value, so `IS_GENERAL=false`, `RUN_CRON=false` or `POSTQUEEN_GENERIC_OAUTH=false` all turn the setting **on**. Remove the variable to turn one off. With Docker Compose, `IS_GENERAL` and `RUN_CRON` also have a default of `true` in `docker-compose.yaml`, so delete their lines there.
</Warning>

`PRISMA_MIGRATE` has its own rule: see [Background work](#background-work).

## Sign-up and sign-in

| Variable | What it does |
|---|---|
| `DISABLE_REGISTRATION` | `true` refuses new accounts once the first workspace exists. Existing accounts sign in as before. People invited without an account cannot create one, except through your own [single sign-on](/configuration/oauth) provider. |
| `IS_GENERAL` | Set it (the Compose file does). It makes `/` open the calendar and shows the Google sign-in button with its companions. Unset, `/` opens analytics and only GitHub sign-in is offered. It does not switch billing: billing turns on only when both Stripe keys are set. |
| `NOT_SECURED` | `true` drops the `Secure` flag from the login cookie so sign-in works over plain HTTP. For a local try only: on a reachable server it sends sessions in the clear. |
| `DISALLOW_PLUS` | Refuses email addresses with a `+`, for signing in as well as signing up, so an existing `you+tag@example.com` account is locked out. Sign-in through Google, GitHub or single sign-on is not affected. |
| `PASSWORDLESS_LOGIN` | `true` signs people in with a one-time code by email. Needs working [email](/configuration/emails). See [Abuse protection and rate limits](/configuration/rate-limits#passwordless-sign-in). |
| `REQUIRE_EMAIL_ACTIVATION` | `true` makes a new email-and-password account click an emailed link before it can sign in, once mail can go out. See [Email](/configuration/emails). |
| `WALLET_LOGIN` | `true` adds **Continue with Wallet** (Solana wallets) to the sign-in and sign-up screens. |
| `MOBILE_APP_SCHEME` | Where `/auth/oauth-mobile-callback` sends a sign-in made from a mobile app of your own. Default `postqueen://auth/callback`. |

### Sign-in buttons

| Button | Shows when | Variables |
|---|---|---|
| Your own OIDC provider | `IS_GENERAL` and `POSTQUEEN_GENERIC_OAUTH` are set. It replaces every other button. | See [Single sign-on (OIDC)](/configuration/oauth) |
| Google | `IS_GENERAL` is set and single sign-on is not | `YOUTUBE_CLIENT_ID`, `YOUTUBE_CLIENT_SECRET`: sign-in shares the YouTube web client and its redirect URI, `/integrations/social/youtube`. There is no `GOOGLE_CLIENT_ID`. Setup: [YouTube setup](/installation/providers/youtube). |
| Apple | Next to Google, once `APPLE_CLIENT_ID` is set | `APPLE_CLIENT_ID` (the Services ID), `APPLE_TEAM_ID`, `APPLE_KEY_ID`, `APPLE_PRIVATE_KEY` (the `.p8` key; write line breaks as `\n`), and optionally `APPLE_APP_BUNDLE_ID` for a native iOS app of your own. Register `NEXT_PUBLIC_BACKEND_URL` + `/auth/oauth/apple/redirect` as the return URL. |
| Farcaster | Next to Google, once `NEYNAR_CLIENT_ID` is set | `NEYNAR_CLIENT_ID` |
| Wallet | Next to Google, when `WALLET_LOGIN` is `true` | `WALLET_LOGIN` |
| GitHub | Only when `IS_GENERAL` is unset | `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` |

Set the four Apple values together: the button appears with `APPLE_CLIENT_ID` alone and fails without the rest.

## Background work

Temporal runs the schedule, and the orchestrator runs its workers. See [Self-hosting overview](/installation/overview#what-runs).

| Variable | What it does |
|---|---|
| `TEMPORAL_ADDRESS` | The Temporal server's `host:port`. `temporal:7233` in the Compose file. Without a reachable server, nothing publishes and no mail is sent. |
| `TEMPORAL_NAMESPACE` | Temporal namespace. Default `default`. |
| `TEMPORAL_TLS` | `true` for a server behind TLS, such as Temporal Cloud. |
| `TEMPORAL_API_KEY` | API key for Temporal Cloud. |
| `RUN_CRON` | Set on **one** backend: at start it launches the recurring workflows, which recover posts that failed to schedule, sync analytics and settle billing. Unset, none of them runs. The Compose file sets it; the Helm chart does not. |
| `ACCOUNT_PURGE_MODE` | The daily purge of what deleted workspaces and users leave behind, three days after deletion. `dry-run` logs what it would remove, `on` removes it, anything else (the default) is off. Independent of `RUN_CRON`. |
| `ACCOUNT_PURGE_HOLD` | Workspace or user ids the purge leaves alone, separated by commas. |
| `PRISMA_MIGRATE` | How the schema is applied at start. Unset, empty, `false`, `False`, `FALSE` or `0` runs `prisma db push --accept-data-loss`; any other value runs `prisma migrate deploy`. See [Backups and upgrades](/installation/backups-and-upgrades#where-the-schema-changes). |
| `ORCHESTRATOR_PORT` | Port of the orchestrator's health endpoint. Default `3002`. |
| `WORKER_CONCURRENCY_DIVIDER` | Divides each network's worker concurrency, so several worker machines together stay within what the network allows. Set it to the number of worker machines. |
| `EXCLUDE_QUEUE` | Queues this worker does not serve, separated by commas, for example `media` to keep it out of video conversion. For pinning a queue to one machine. |

## Storage and media

Setup and trade-offs: [Uploads and storage](/configuration/uploads) and [Cloudflare R2](/configuration/r2).

| Variable | What it does |
|---|---|
| `STORAGE_PROVIDER` | `local` (the default when unset) or `cloudflare`. |
| `UPLOAD_DIRECTORY` | Where `local` storage writes files. Required with `local`: without it the backend does not start. In the official image it must be `/uploads`, the folder nginx serves. |
| `NEXT_PUBLIC_UPLOAD_STATIC_DIRECTORY` | The URL path for local files, without slashes: `uploads`. |
| `PREVIOUS_FRONTEND_URLS` | Addresses a `local` install used to run under, separated by commas. At start, stored file addresses under them move to the current `FRONTEND_URL`. See [Uploads and storage](/configuration/uploads#move-to-a-new-address). |
| `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_ACCESS_KEY`, `CLOUDFLARE_SECRET_ACCESS_KEY`, `CLOUDFLARE_BUCKETNAME` | The R2 account, token and bucket. |
| `CLOUDFLARE_BUCKET_URL` | The public address media is read from: a custom domain, the `r2.dev` address, or your own `https://postqueen.example.com/api/uploads`. Never the `r2.cloudflarestorage.com` API endpoint. |
| `CLOUDFLARE_REGION` | Usually `auto`. |
| `CLOUDFLARE_JURISDICTION` | Only for a bucket created with a jurisdiction, such as `eu`. |
| `UPLOAD_VIA_SERVER` | `true` sends R2 uploads through the backend instead of from the browser straight to the bucket. |
| `UPLOAD_TMP_DIR` | Where uploads wait while they are written to storage, and where ffmpeg works. Default: the system temp folder. Keep about 2.5 times the largest upload free. |
| `MEDIA_PROCESSING_CONCURRENCY` | How many uploaded videos one orchestrator converts at once. Default `1`. |
| `FFMPEG_PATH`, `FFPROBE_PATH` | Only outside the image, which ships both: point them at an ffmpeg build with libass. |
| `FFMPEG_TIMEOUT_MS` | Limit for one ffmpeg run, in milliseconds. Default 20 minutes. |
| `DISABLE_IMAGE_COMPRESSION` | Skips the browser's image compression before upload, to keep originals byte for byte. |

## Limits and safety

| Variable | What it does |
|---|---|
| `API_LIMIT` | Posts created through the public API per workspace per hour. Default 90; the Compose file sets 30. |
| `UPLOAD_LIMIT` | Uploads per workspace per hour, through the public API and the app together. Default 300. |
| `RESTRICT_UPLOAD_DOMAINS` | One piece of text that every media URL in a public API post must contain, usually your media host. A plain text match, not a list. |
| `DISABLE_SSRF_PROTECTION` | `true` lets the server fetch private and local addresses: a WordPress, Mastodon, Lemmy, Listmonk or Bluesky server on your own network, webhooks and media downloads. Refused requests fail as `fetch failed` with `Blocked IP` in the log. It applies to the whole install, so set it only when everyone who can add a channel or a webhook is trusted. |
| `GUARD_*`, `TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET` | Sign-in rate limits and an optional captcha: see [Abuse protection and rate limits](/configuration/rate-limits). |

### Farcaster

The channel connects through a Neynar managed signer, which the person approves by scanning a QR code in the Farcaster app. There is no redirect URI.

| Variable | What it is |
|---|---|
| `NEYNAR_SECRET_KEY` | Your Neynar API key. |
| `NEYNAR_APP_FID` | The Farcaster ID of the account that represents your app. Without it and the next one, the connect stops with "Farcaster is not configured". |
| `NEYNAR_APP_MNEMONIC` | The recovery phrase of that account's wallet. It signs the signer requests. Keep it like a private key. |
| `NEYNAR_SPONSOR_SIGNERS` | `true` lets Neynar pay the signer fee from your Neynar credits. Otherwise the person pays it in the Farcaster app. |
| `NEYNAR_CLIENT_ID` | Only shows the **Continue with Farcaster** sign-in button. The channel does not use it. |

`NEYNAR_APP_FID`, `NEYNAR_APP_MNEMONIC` and `NEYNAR_SPONSOR_SIGNERS` are not listed in the Compose file's YAML; the `.env` file passes them through. Setup: [Farcaster setup](/installation/providers/farcaster).

### Hide or move a network

| Variable | What it does |
|---|---|
| `HIDDEN_PROVIDERS` | Network identifiers to leave out of **Add Channel**, separated by commas, for example `tiktok,x`. Channels already connected keep working. |
| `MIGRATE_PROVIDERS` | `old:new` pairs, separated by commas, for example `tiktok:tiktok-business`. Reconnecting an `old` channel then runs the `new` network's sign-in and moves the channel over, keeping its id, scheduled posts and settings. Facebook Page, Instagram through Facebook, LinkedIn Page, YouTube, Google Business Profile and Tumblr cannot be a target. |

The identifier is the last part of the connect address, such as `tiktok` in `/integrations/social/tiktok`. The two are usually set together: hide the network you retire, and its channels move on their next reconnect.

## MCP and OAuth apps

Details: [MCP on your server](/configuration/mcp).

| Variable | What it does |
|---|---|
| `NEXT_PUBLIC_OVERRIDE_BACKEND_URL` | The base address MCP's OAuth discovery advertises for the resource, the issuer and the token, registration and userinfo endpoints. Falls back to `NEXT_PUBLIC_BACKEND_URL`. Set it to a host that serves the backend at its root: see [Split deployments](/reverse-proxies/split-deployments#give-the-backend-its-own-host). |
| `DCR_VERIFIED_DOMAINS` | Domains, separated by commas, that self-registering OAuth clients may send people back to. With a list, an `https` callback must be on a listed domain or a subdomain of one. `localhost` and app schemes such as `cursor://` are not checked. Unset, any `https` callback registers. |
| `OPENAI_OAUTH_CLIENT_ID` | The client id of a ChatGPT app you published. Turns on the `openid` and `email` scopes and the `/oauth/userinfo` endpoint, for that client and for self-registered clients whose callbacks are all on a `DCR_VERIFIED_DOMAINS` domain. |
| `OPENAI_APP_CHALLANGE` | The domain verification string OpenAI gives you, served at `/.well-known/openai-apps-challenge`. The misspelling is the name the code reads. |
| `MCP_ONLY` | Serves only MCP and its OAuth routes, for an instance that exists for that alone. The web app and the public API stop working on it. |
| `AGENT_API_KEY` | Secret for `POST /public/agent`, which turns a text brief into a post. Unset, the route refuses every request. |
| `ENTERPRISE_SECRET` | Key for a few provisioning routes used by reseller integrations. Unset, they refuse every request. If you set it, use a value of its own. |

## Listed in example files, but not read

These appear in the Compose file or `.env.example` and change nothing: `FEE_AMOUNT`, `NX_ADD_PLUGINS`, `SLACK_SIGNING_SECRET`, `STRIPE_SIGNING_KEY_CONNECT`, `POSTQUEEN_OAUTH_URL` and `BACKEND_URL`. `MCP_URL` is passed to the web app, but no page uses it: the MCP addresses on **Connections** come from `NEXT_PUBLIC_BACKEND_URL`.
