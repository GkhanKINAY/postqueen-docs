These are the tools PostQueen answers over MCP, with every parameter and every field they send back. Your agent reads these schemas on connect, so you never call one by hand.

## How many tools you get

The count depends on the address your client connects to.

| Address | Tools | Notes |
|---|---|---|
| `https://api.postqueen.ai/mcp/YOUR_API_KEY` | **21** | The API key in the URL. The address to start with |
| `https://api.postqueen.ai/mcp` with `Authorization: Bearer YOUR_API_KEY` | **21** | The same tools, with the key (or a `pos_` OAuth token) in a header |
| `https://api.postqueen.ai/sse/YOUR_API_KEY` | **21** | Legacy [SSE transport](/mcp/limits-and-troubleshooting#transports-you-may-notice-and-should-not-build-on). Prefer the two addresses above |
| `https://api.postqueen.ai/mcp-oauth-dynamic` | **20** | Sign in instead of pasting a key. Everything except `ask_postqueen`. Not tested by PostQueen yet |

The sign-in address is an option for clients that support MCP OAuth. Your client registers itself, you sign in to PostQueen, and a workspace admin approves the connection. The access does not expire on its own: revoke it under **Connections > Approved Apps**. No client has completed this sign-in in PostQueen's own tests yet, so the API key address is the one to start with, and some clients cannot use the sign-in at all. Each agent's setup page says which address to use.

The API key is under **Connections > API Keys** in the app. Only a workspace admin can reveal it, and each workspace has one.

## The 21 tools

| Group | Tools |
|---|---|
| Channels | `integrationList`, `groupList`, `integrationSchema`, `triggerTool` |
| Posts | `integrationSchedulePostTool`, `postsListTool`, `postReadTool`, `postSettingsTool` |
| Analytics | `analyticsSummaryTool`, `analyticsPostsTool`, `analyticsPostTool` |
| Media | `generateImageTool`, `uploadFromUrlTool`, `uploadWidgetTool`, `uploadWidgetTicketTool`, `uploadWidgetStatusTool` |
| Video | `generateVideoOptions`, `videoFunctionTool`, `generateVideoTool`, `videoStatusTool` |
| Agent | `ask_postqueen` (key and Bearer addresses only) |

The in-app AI Copilot runs most of the same tools. The three upload widget tools and `ask_postqueen` exist only over MCP.

## integrationList

List all connected social media accounts (channels) for your organization.

**Parameters:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `group` | string | No | Group (customer) ID from `groupList`. When provided, only channels belonging to that group are returned |

**Returns:**

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Integration ID (use this when scheduling posts) |
| `name` | string | Display name of the account |
| `picture` | string | Profile picture URL |
| `platform` | string | Platform identifier (e.g., `x`, `linkedin`, `facebook`) |

Four fields and no more. The list leaves out channels that are disabled, need a reconnect, or are not fully connected yet, so every channel it returns can take a post. A channel's group and profile never reach your client. Read those from [`GET /integrations`](/public-api/integrations/list) instead.

## groupList

List all groups (customers) for your organization. Use a group's `id` with `integrationList` to filter channels down to a single group.

**Parameters:** None

**Returns:**

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Group (customer) ID (pass to `integrationList` as `group`) |
| `name` | string | Group (customer) display name |

## integrationSchema

Get the posting rules, character limits, and required settings for a specific platform. The response also lists the platform's helper tools. Call this before scheduling a post to understand what the platform expects.

**Parameters:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `isPremium` | boolean | Yes | Whether the user has a premium subscription |
| `platform` | string | Yes | Platform identifier (e.g., `x`, `linkedin`, `reddit`, `discord`) |

**Returns:**

| Field | Type | Description |
|-------|------|-------------|
| `rules` | string | Platform-specific posting rules and best practices |
| `maxLength` | number | Maximum character length for posts |
| `settings` | object | JSON schema of required settings for this platform |
| `tools` | array | Platform-specific helper tools (see `triggerTool`) |

The `tools` array contains helper functions specific to the platform. For example, Discord returns a tool to list available channels, Reddit returns a tool to search for subreddits, and Pinterest returns a tool to list boards.

Each tool in the array has:

| Field | Type | Description |
|-------|------|-------------|
| `methodName` | string | Function name to pass to `triggerTool` |
| `description` | string | What the tool does |
| `dataSchema` | array | Parameters the tool accepts |

## triggerTool

Execute a platform-specific helper function. These are discovered through `integrationSchema` and are used to fetch dynamic data like channel lists, subreddit suggestions, or page IDs. Every tool each network offers is catalogued in [Provider Tools](/public-api/integrations/provider-tools).

**Parameters:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `integrationId` | string | Yes | The integration ID from `integrationList` |
| `methodName` | string | Yes | The function name from `integrationSchema` tools |
| `dataSchema` | array | Yes | Key-value pairs of parameters for the function |

Each item in `dataSchema`:

| Field | Type | Description |
|-------|------|-------------|
| `key` | string | Parameter name |
| `value` | string | Parameter value |

**Example use cases:**
- Get the list of Discord channels for a server
- Search for Reddit subreddits
- List Pinterest boards
- List Slack channels
- Search Instagram audio (`audioSearch`) to attach to a Reel (available only on Facebook Business-linked Instagram channels)

## integrationSchedulePostTool

Schedule, draft, or immediately publish posts to social media platforms. This is the main tool for creating content.

The name your client sees, and the name in validation errors ("try `integrationSchedulePostTool` again"), is **`integrationSchedulePostTool`**.

**Parameters:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `socialPost` | array | Yes | Array of posts to create |

Each item in `socialPost`:

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `integrationId` | string | Yes | Integration ID from `integrationList` |
| `isPremium` | boolean | Yes | Whether the user has premium |
| `date` | string | Yes | UTC datetime (e.g., `2026-08-01T09:00:00.000Z`) |
| `shortLink` | boolean | Yes | Whether to shorten links in the post |
| `type` | string | Yes | `draft`, `schedule`, or `now` |
| `postsAndComments` | array | Yes | The post content and optional comments |
| `settings` | array | Yes | Platform-specific settings from `integrationSchema` |

Each item in `postsAndComments`:

| Field | Type | Description |
|-------|------|-------------|
| `content` | string | HTML content (see formatting rules below) |
| `attachments` | array | Array of image/media URLs |
| `delay` | number | Optional. Minutes to wait after the previous item before this comment or thread item goes out. `0` or omitted means right after |

Each item in `settings`:

| Field | Type | Description |
|-------|------|-------------|
| `key` | string | Setting name |
| `value` | any | Setting value (prefer IDs over labels when available) |

### Content Formatting

Content must be HTML with these allowed tags only:

| Tag | Usage |
|-----|-------|
| `<p>` | Wrap each line |
| `<h1>`, `<h2>`, `<h3>` | Headings |
| `<strong>` | Bold text |
| `<u>` | Underlined text |
| `<ul>`, `<li>` | Lists |

<Warning>
You cannot combine `<u>` and `<strong>` in the same element. Each line of text must be wrapped in `<p>` tags.
</Warning>

### Posts vs Comments

The `postsAndComments` array behavior depends on the platform:

- **Thread-based platforms** (X, Threads, Bluesky): Each array item becomes a separate post in a thread
- **Comment-based platforms** (LinkedIn, Facebook): First item is the post, remaining items are comments

### Multiple Posts

To schedule multiple posts (e.g., 20 posts across different days), add multiple items to the `socialPost` array, each with its own `date` and `integrationId`.

**Returns:** An array of results, one per post in `socialPost`, each with:

| Field | Type | Description |
|-------|------|-------------|
| `postId` | string | The created post ID |
| `integration` | string | The integration it was posted to |

If validation fails, returns `{ errors: string }` with details about what went wrong (e.g., content exceeds character limit).

## postsListTool

List the posts scheduled between two dates, whatever their state: scheduled, draft, published or failed. It reads the same posts as [List Posts](/public-api/posts/list), with the channel flattened into three fields instead of a nested object, and each item carries the post's current settings. To see everything upcoming, pass a wide window starting now.

**Parameters:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `startDate` | string | Yes | Start of the window, UTC (e.g., `2026-07-20T00:00:00`) |
| `endDate` | string | Yes | End of the window, UTC (e.g., `2026-08-20T00:00:00`) |
| `customer` | string | No | Group (customer) ID from `groupList`, to keep only that group's channels |

**Returns:** `posts`, an array with one item per post:

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Post ID (pass it to `postReadTool` or `postSettingsTool`) |
| `publishDate` | string | UTC time the post is set for |
| `state` | string | `QUEUE`, `DRAFT`, `PUBLISHED` or `ERROR` |
| `content` | string | The post content |
| `settings` | object | The post's current platform settings |
| `group` | string | Group ID of the post and its comments or thread items |
| `integrationId` | string | ID of the channel the post goes to |
| `platform` | string | Platform identifier (e.g., `x`, `linkedin`) |
| `integrationName` | string | Display name of the channel |

---

## postReadTool

Read one existing post in full: the post and its comments or thread items, each with its own id, content, media and delay, plus its channel, state, publish date and settings. Use it with an id from `postsListTool` before showing, changing or rescheduling a post. It only reads.

**Parameters:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | string | Yes | Post ID from `postsListTool` (the first item of a thread) |

**Returns:** `output`, with:

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Post ID |
| `group` | string | The post's group ID |
| `integrationId` | string | ID of the channel the post goes to |
| `platform` | string | Platform identifier (e.g., `x`, `bluesky`) |
| `integrationName` | string | Display name of the channel |
| `state` | string | `QUEUE`, `DRAFT`, `PUBLISHED` or `ERROR` |
| `publishDate` | string | UTC time the post is set for |
| `settings` | object | The post's platform settings |
| `posts` | array | The post, then each comment or thread item: `id`, `content`, `delay` (minutes after the previous item) and `attachments` (`id`, `path`) |

If the post does not exist, returns `{ error: "Post not found" }`.

---

## postSettingsTool

Change the platform settings of a post that has not gone out yet: a scheduled post whose time is still ahead, or a draft. Only the settings change. The content and the publish date stay exactly as they are.

The keys you pass are merged into the post's existing settings, so send only what should change. `integrationSchema` tells you which keys the platform has. A scheduled post is validated again with the merged settings, the same way a new post is.

**Parameters:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | string | Yes | Post ID, usually from `postsListTool` |
| `settings` | array | Yes | The keys to change |

Each item in `settings`:

| Field | Type | Description |
|-------|------|-------------|
| `key` | string | Setting name |
| `value` | any | New value (prefer IDs over labels when available) |

**Returns:**

| Field | Type | Description |
|-------|------|-------------|
| `postId` | string | The updated post ID |
| `publishDate` | string | The post's publish date, unchanged |

If the update is refused, returns `{ errors: string }` instead: the post was not found, it already published or failed, its time has passed, the id belongs to a comment rather than the main post, or the merged settings did not validate. The same operation over HTTP: [Update Post Settings](/public-api/posts/settings).

## generateImageTool

Generate an AI image to use as a post attachment.

**Parameters:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `prompt` | string | Yes | Description of the image to generate |
| `style` | string | No | Realistic, Cartoon, Anime, Minimalist, Sketch or Watercolor. Realistic when omitted |
| `orientation` | string | No | `square`, `portrait` or `landscape`. Square when omitted |

**Returns:**

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Media ID |
| `path` | string | URL of the generated image |
| `alt` | string | Alt text, when there is one |
| `thumbnail` | string | Thumbnail URL, when there is one |

On failure, returns `{ error: string }` instead, for example when the account has no AI image credits left.

Use the returned `path` in the `attachments` array when scheduling a post.

## uploadFromUrlTool

Upload a remote image or video into the media library from a public URL. Use this before scheduling a post when the user provides an external media URL that is not already hosted on your PostQueen domain, so the attachment passes the upload-domain validation.

**Parameters:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `url` | string | Yes | The public URL of the image or video to upload |

**Returns:**

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Media ID |
| `path` | string | URL of the hosted media |
| `status` | string | `ready`, or `processing` while a video is being prepared |

On failure, returns `{ error: string }` instead (for example, the URL could not be fetched, the file type is not allowed, or the file exceeds the size limit).

**File types a post accepts:** PNG, JPEG, GIF and WebP images, and MP4 video. A MOV file is converted to MP4 before the tool answers. An MP4 comes back `processing` and can be attached right away.

Size caps are enforced server-side.

Use the returned `path` in the `attachments` array when scheduling a post.

## uploadWidgetTool

Show an **Upload Media** panel in the chat, where you add a photo or video from your own device to the media library. It works in clients that display MCP Apps panels, such as Claude, Claude Cowork and ChatGPT. In other clients no panel appears, so use `uploadFromUrlTool` with a public URL instead.

**Parameters:** None

**Returns:**

| Field | Type | Description |
|-------|------|-------------|
| `sessionId` | string | Identifies this upload panel. Pass it to `uploadWidgetStatusTool` |

The files you upload are reported back in the conversation. On failure, returns `{ error: string }`.

Used by the upload panel itself, not by your agent: it gets a short-lived upload ticket for the `sessionId` that `uploadWidgetTool` returned. Clients that support MCP Apps keep it out of the model's view.

**Parameters:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `sessionId` | string | Yes | The `sessionId` from `uploadWidgetTool` |

**Returns:** `ticket`, or `{ error: string }`.

## uploadWidgetStatusTool

List what you uploaded through the upload panel.

**Parameters:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `sessionId` | string | Yes | The `sessionId` from `uploadWidgetTool` |

**Returns:** `media`, an array with one item per file:

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Media ID |
| `path` | string | URL of the hosted media |
| `status` | string | `ready`, or `processing` while a video is being prepared. Wait about 10 seconds and call again |
| `error` | string | Why a file could not be prepared, when that happened |

An empty list means nothing has been uploaded yet. A file whose status is `ready` can go in the `attachments` array when scheduling a post.

## generateVideoTool

Start generating a video to use as a post attachment. A video takes a few minutes, so this call only starts the job and hands back a `jobId`. `videoStatusTool` reports when it is ready.

**Parameters:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `identifier` | string | Yes | Video type from `generateVideoOptions` |
| `output` | string | Yes | `vertical` or `horizontal` |
| `customParams` | array | Yes | Key-value pairs of parameters for the video type |

Each item in `customParams`:

| Field | Type | Description |
|-------|------|-------------|
| `key` | string | Parameter name |
| `value` | any | Parameter value |

**Returns:**

| Field | Type | Description |
|-------|------|-------------|
| `jobId` | string | Pass it to `videoStatusTool` |

On failure, returns `{ error: string }` instead, for example *No AI video credits are available on this account*. A job that fails to start does not use a video credit.

## videoStatusTool

Check on a video started with `generateVideoTool`. While the status is `pending`, the tool asks your agent to wait about 30 seconds and call again.

**Parameters:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `jobId` | string | Yes | The `jobId` that `generateVideoTool` returned |

**Returns:**

| Field | Type | Description |
|-------|------|-------------|
| `status` | string | `pending`, `completed` or `failed` |
| `id` | string | Media ID, once the video exists |
| `url` | string | URL of the finished video |
| `error` | string | Why the job failed |

Use the returned `url` in the `attachments` array when scheduling a post. Whatever your agent schedules with these tools lands on the PostQueen calendar, so you can still open it and change your mind.

## analyticsSummaryTool

Workspace totals for published posts, the same numbers as Analytics → All channels → Summary.

**Parameters:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `date` | 7, 30 or 90 | No | Publish-date window in days. Default 30 |
| `integrationId` | string | No | Channel id from `integrationList`, to limit to one channel |
| `platform` | string | No | Provider identifier such as `x`, `instagram`, `linkedin-page` |

**Returns:** `posts`, `reactions`, `comments` and `impressions`. Totals are current lifetime counts, not "likes that happened inside this window". Null is unknown, never zero.

## analyticsPostsTool

Ranked post performance, the same numbers as Analytics → Top posts and Performance per post. Use this for "top posts" or "how did the post about X do" when you do not have a post id yet.

**Parameters:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `date` | 7, 30 or 90 | No | Publish-date window in days. Default 30 |
| `sort` | string | No | `reactions`, `comments`, `impressions`, `engagement` or `published`. Default `reactions` |
| `dir` | `asc` or `desc` | No | Sort direction |
| `page` | number | No | Page index, from 0 |
| `limit` | number | No | Page size, 1–20. Default 5 |
| `integrationId` | string | No | Channel id from `integrationList` |
| `platform` | string | No | Provider identifier such as `x` or `instagram` |
| `q` | string | No | Search caption, channel name, platform or post id |

Null is unknown, not zero.

Current lifetime totals for one published post. Use this when you already have a post id from `analyticsPostsTool` or `postsListTool`.

**Parameters:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `postId` | string | Yes | Post id from `analyticsPostsTool` or `postsListTool` |

If `error` is `missing_release`, the published content still needs connecting in the app (Connect Post). Do not invent numbers.

## `ask_postqueen`

The 21st tool is not like the 20 above. It is on the API key and Bearer addresses only, not on the sign-in address. Your client will discover it anyway, so it is worth knowing what it is.

It takes one parameter, `message`, a plain-language request. Behind it sits the same assistant you talk to in the app, running server-side with the same tools listed above and the same access to your calendar. So "schedule a launch post for Thursday" is a single call rather than a sequence your own agent has to plan.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `message` | string | Yes | What you want PostQueen to do, in your own words |

Two things follow from that. It can write to your calendar, so treat it with the same care as `integrationSchedulePostTool`. And because PostQueen plans the steps itself, you get less control over exactly which tools run than you would calling them directly.

## What these tools cannot do

Some jobs have no tool here and need the CLI or the API alongside. `ask_postqueen` does not change this: it drives the same tools, so it has the same gaps. Deleting a post is one. Moving one to a new time is another, because `postSettingsTool` changes settings and nothing else. Analytics for published posts is in this set (`analyticsSummaryTool`, `analyticsPostsTool`, `analyticsPostTool`); channel numbers such as follower growth are on the API and the CLI. [Limits and Troubleshooting](/mcp/limits-and-troubleshooting) has the full list, the route to use instead of each gap, and what to check when your client says it cannot reach PostQueen at all.
