Point a client at your MCP address and your agent gets **21 tools** to list channels, upload media, schedule posts and read post analytics. Nothing to install.

<Note>
**You do not have to run or install anything.** In the protocol's own words PostQueen is the "server" and your AI client is the "client", but PostQueen is already running at a URL. Setup is pasting that URL into your client.
</Note>

## Authentication

Start with the API key address. Two forms, the same 21 tools:

| Form | URL | Header |
|---|---|---|
| Key in the URL | `https://api.postqueen.ai/mcp/YOUR_API_KEY` | none |
| Bearer | `https://api.postqueen.ai/mcp` | `Authorization: Bearer YOUR_API_KEY` (or a `pos_` OAuth token) |

The URL form accepts API keys only. The key is under **Connections > API Keys** in the app. Only a workspace admin can reveal it, and each workspace has one. Building for other users: [OAuth2](/public-api/oauth). Self-hosted: swap the host for your `NEXT_PUBLIC_BACKEND_URL`.

### Sign in instead of a key (not tested yet)

Clients that support MCP OAuth can use `https://api.postqueen.ai/mcp-oauth-dynamic` with no key. The client registers itself, you sign in to PostQueen, and a workspace admin approves the connection. It exposes 20 tools, everything except `ask_postqueen`. The access does not expire on its own; revoke it under **Connections > Approved Apps**. PostQueen has not completed this sign-in in its own tests yet, and some clients cannot use it, so each agent page says which address to use.

Tool names, parameters, and how many tools each address exposes: [Tools Reference](/mcp/tools#how-many-tools-you-get).
