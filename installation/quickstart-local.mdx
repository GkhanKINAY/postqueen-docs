This runs the whole stack on your own computer, over plain HTTP on `http://localhost:4007`. Nothing is exposed to the internet, and one command removes it when you are done.

<Warning>
**Not for a server.** This setup turns on `NOT_SECURED=true` so the login cookie works without HTTPS. For an install other people use, follow [Deploy to a server](/installation/production) instead.
</Warning>

## Before you start

| | |
|---|---|
| Docker | [Docker Desktop](https://www.docker.com/products/docker-desktop/) on macOS or Windows, or [Docker Engine](https://docs.docker.com/engine/install/) with the Compose plugin on Linux |
| Compose | v2.24 or newer. Check with `docker compose version` |
| Memory | About 4 GB free for Docker. In Docker Desktop, set it under **Settings > Resources** |
| Ports | 4007, 7233 and 8080 free on your computer |

## Start PostQueen

<Steps>
  <Step title="Clone the Compose repository">
    ```bash
    git clone https://github.com/GkhanKINAY/postqueen-docker-compose
    cd postqueen-docker-compose
    ```

    Run every command on this page from this folder. It holds `docker-compose.yaml` and the `dynamicconfig` folder that Temporal reads when it starts, so clone it rather than copying the YAML alone.
  </Step>
  <Step title="Write the .env file">
    ```bash
    cat > .env <<EOF
    JWT_SECRET=$(openssl rand -hex 32)
    ENCRYPTION_KEY=$(openssl rand -hex 32)
    NOT_SECURED=true
    EOF
    ```

    The Compose file reads `.env` from this folder. `JWT_SECRET` signs sessions, `ENCRYPTION_KEY` encrypts the credentials PostQueen stores, and `NOT_SECURED=true` lets the login cookie work over HTTP. Everything else keeps the Compose file's defaults, which point PostQueen at `http://localhost:4007`.
  </Step>
  <Step title="Start the stack">
    ```bash
    docker compose up -d
    ```

    The first run downloads the images, which takes a few minutes. Eight containers start: `postqueen`, its PostgreSQL and Redis, and five for Temporal (the server, its PostgreSQL and Elasticsearch, the admin tools and the web UI).
  </Step>
  <Step title="Wait for the backend">
    ```bash
    docker compose logs -f postqueen
    ```

    On first boot PostQueen creates its database schema, then starts. Wait for this line, then press `Ctrl+C` to stop following the log (the container keeps running):

    ```text
    Backend started successfully on port 3000
    ```

    A few lines later the backend checks its settings. `Configuration check completed without any issues` means the basics are right. A `Configuration issue` line names the variable to fix.
  </Step>
  <Step title="Create the first account">
    Open **http://localhost:4007** and sign up. No mail server is configured, so the account is active at once.

    <Check>
    PostQueen opens the calendar, and a short tour of the app may start. There are no channels yet. That is a healthy fresh install.
    </Check>

    The Temporal web UI is at http://localhost:8080 if you want to watch scheduled work. You do not need it.
  </Step>
</Steps>

## Connect a channel

Eight networks need nothing from you: Bluesky, DEV, Hashnode, Lemmy, Listmonk, Moltbook, Nostr and WordPress take a key or a login in the connect form. Open **Channels** in the left rail, choose **Add Channel** and pick one.

The other networks need a developer app that you register with the network. Put its keys in `.env` and recreate the app container:

Many networks refuse an `http://localhost` redirect address, and some fetch your media from its URL, which a laptop cannot serve to the internet. For those, use a domain and HTTPS: [Deploy to a server](/installation/production). [Channel developer apps](/installation/providers/overview) lists each network's variables and setup page.

## If something goes wrong

<AccordionGroup>
  <Accordion title="localhost:4007 does not load">
    Give the first boot a minute or two: the schema is created before the web app answers. `docker compose ps` shows each container's state, and `docker compose logs -f postqueen` shows where the start is.
  </Accordion>
  <Accordion title="Signing in sends me back to the login page">
    The browser dropped the `Secure` login cookie over HTTP. Check that `.env` has `NOT_SECURED=true`, then recreate the `postqueen` container with the command above.
  </Accordion>
  <Accordion title="A port is already in use">
    Another program uses 4007, 7233 or 8080. Stop it, or change the left-hand number of that port in `docker-compose.yaml`. With `"4017:5000"`, PostQueen answers on `http://localhost:4017`, and `MAIN_URL`, `FRONTEND_URL` and `NEXT_PUBLIC_BACKEND_URL` in `.env` must use the same port.
  </Accordion>
  <Accordion title="Containers restart or get killed">
    Almost always memory. Give Docker about 4 GB, then run `docker compose up -d` again.
  </Accordion>
</AccordionGroup>

[Self-hosting troubleshooting](/troubleshooting/self-host) covers more.

## Stop or remove it

| Command | What it does |
|---|---|
| `docker compose stop` | Stops the containers and keeps all data |
| `docker compose start` | Starts them again |
| `docker compose down` | Removes the containers and keeps the data volumes |
| `docker compose down -v` | Removes the containers **and deletes every volume**: the database, uploads and scheduled work |

<Warning>
`-v` cannot be undone. Leave it off if you might want the test data back.
</Warning>
