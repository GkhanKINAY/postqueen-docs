On a self-hosted PostQueen the Threads app is yours. Threads needs a Meta app of its own, created with the Threads use case. It is not the [Facebook app](/installation/providers/facebook) and not the Instagram (Standalone) app from [Instagram setup](/installation/providers/instagram).

## Before you start

| | |
|---|---|
| Developer console | [Meta for Developers](https://developers.facebook.com/apps), with a Meta developer account |
| Variables | `THREADS_APP_ID`, `THREADS_APP_SECRET` |
| Redirect URI | `FRONTEND_URL` + `/integrations/social/threads`, `https` only |
| Permissions | `threads_basic`, `threads_content_publish`, `threads_manage_replies`, `threads_manage_insights` |
| Callback URLs | `NEXT_PUBLIC_BACKEND_URL` + `/integrations/threads/platform-deauthorize` and `/integrations/threads/platform-deletion` |
| Review | Only Threads Testers on the app can connect until Meta approves each permission and the app is published |

<Warning>
PostQueen does not check the granted Threads permissions when an account connects. With one missing, the channel connects and looks healthy, and posting, replies or analytics fail later. Add all four permissions before anyone connects.
</Warning>

## Create the app

<Steps>
  <Step title="Start a new app">
    Open [Create an app](https://developers.facebook.com/apps/creation/) in Meta for Developers. Enter the app name and a contact email, then choose **Next**.
  </Step>
  <Step title="Pick the Threads use case">
    On the use case step, select **Access the Threads API** and choose **Next**. Connect a business portfolio now or skip it, then finish the remaining steps and create the app.
  </Step>
  <Step title="Add the permissions">
    In the app dashboard, open **Use cases**, then **Customize** on **Access the Threads API**, then **Permissions**. `threads_basic` is already there and cannot be removed. Add `threads_content_publish`, `threads_manage_replies` and `threads_manage_insights`.

    PostQueen asks for these four and no others. Do not add `threads_profile_discovery` or the other optional permissions, and do not add `instagram_*` or `pages_*` permissions to this app.
  </Step>
  <Step title="Add the redirect URI">
    Open **Settings** in the same use case. Enter the redirect URI in **Redirect Callback URLs**, then save.

    <OAuthRedirect />

    Threads accepts only `https` redirects. When `FRONTEND_URL` is plain `http`, PostQueen sends the callback through `https://redirectmeto.com/` first, and that wrapped address is the one to register:

    <CodeGroup>

    ```text Your domain
    https://postqueen.example.com/integrations/social/threads
    ```

    ```text Local development
    https://redirectmeto.com/http://localhost:4200/integrations/social/threads
    ```

    ```text Docker on your machine
    https://redirectmeto.com/http://localhost:4007/integrations/social/threads
    ```

    </CodeGroup>
  </Step>
  <Step title="Set the callback URLs">
    In the same **Settings**, set:

    - **Uninstall Callback URL**: `NEXT_PUBLIC_BACKEND_URL` + `/integrations/threads/platform-deauthorize`
    - **Delete Callback URL**: `NEXT_PUBLIC_BACKEND_URL` + `/integrations/threads/platform-deletion`

    With the backend at `https://postqueen.example.com/api`, the first is `https://postqueen.example.com/api/integrations/threads/platform-deauthorize`. Removing the app on Threads flags that account's channels for reconnection, and a deletion request deletes them and their posts. Meta only calls a public `https` address, so skip this step on a local install.
  </Step>
  <Step title="Copy the Threads app ID and secret">
    In the same **Settings**, copy the **Threads App ID** and the **Threads App secret** (choose **Show**). A Threads app has two app IDs: these are not the App ID and App secret under **App settings > Basic**.
  </Step>
  <Step title="Add the Threads accounts that will connect">
    While the app is in development, only Threads Testers can connect. Open **App roles > Roles**, choose **Add People**, pick **Threads Tester** and enter the Threads username.

    The invited account accepts on Threads, in **Settings > Account > Website permissions**, on the **Invites** tab.
  </Step>
</Steps>

## Set the variables

Add the two keys to your environment:

```env
THREADS_APP_ID="your threads app id"
THREADS_APP_SECRET="your threads app secret"
```

<RestartAndAddChannel />

Pick **Threads**, sign in with an account that accepted the tester invitation, and approve every permission. The connection renews itself, so nobody has to reconnect on a schedule.

## App review

A new Threads app starts in development. Until Meta approves it, only Threads Testers on the app can connect, and nobody else can grant its permissions.

To let anyone connect, request approval for each of the four permissions in **App Review** and verify your business portfolio. Meta asks for a description and a screen recording of how the app uses each permission. Then publish the app: Meta asks for an app icon, a privacy policy URL and a data deletion URL first, and in the EU a contact for a Data Protection Officer. Request only the four permissions in the table above.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Threads shows an error about the redirect URI">
    The redirect URI PostQueen sent is not in **Redirect Callback URLs**, or differs from it. On a plain `http` install, register the `redirectmeto.com` address from the table, not the bare `localhost` one.
  </Accordion>
  <Accordion title="The account cannot authorize the app">
    It is not a Threads Tester on the app, or it has not accepted the invitation. Add it under **App roles > Roles**, accept the invitation in Threads under **Website permissions**, and connect again.
  </Accordion>
  <Accordion title="The channel connected, but replies or analytics fail">
    A permission is missing from the app, and PostQueen does not check Threads permissions at connect. Add all four, then reconnect the channel and approve everything.
  </Accordion>
  <Accordion title="Threads access token expired">
    The account's token could not be renewed. Reconnect the channel.
  </Accordion>
</AccordionGroup>
