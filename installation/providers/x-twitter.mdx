On a self-hosted PostQueen the X app is yours. PostQueen connects X accounts with OAuth 1.0a and publishes through the X API v2, so it reads only the app's **Consumer Keys**. The OAuth 2.0 Client ID and secret, the Bearer token and your own account's access token are not used.

## Before you start

| | |
|---|---|
| Developer console | [X Developer Console](https://console.x.com), signed in with the X account that will own the app |
| Variables | `X_API_KEY`, `X_API_SECRET` |
| Callback URL | `FRONTEND_URL` + `/integrations/social/x`, or `X_URL` + `/integrations/social/x` when `X_URL` is set |
| Permissions | OAuth 1.0a, **Read and write** |
| Cost | Pay-per-use credits you buy in the console. X's pricing page lists \$0.015 per post created and \$0.20 per post that contains a URL (checked September 2026) |
| Review | No review step in X's getting-started docs. The app works once it has credits and the settings below |

## Create the app

<Steps>
  <Step title="Sign in to the Developer Console">
    Open the [Developer Console](https://console.x.com) and sign in with the X account that will own the app. Accept the Developer Agreement and Policy, and fill in how you will use the API.
  </Step>
  <Step title="Buy credits">
    The X API has no free tier. Buy credits in the console before you connect anything: every post PostQueen creates is charged against them, and so are PostQueen's analytics and automation reads. Set a spending limit per billing cycle if you want a cap.
  </Step>
  <Step title="Create the app">
    Create a new app and enter its name, description and use case. The console then shows the app's keys once: you only need the **API Key** and **API Key Secret**, the Consumer Keys, from it. Store them safely.
  </Step>
  <Step title="Set up user authentication">
    Open the app's **User authentication settings** and set:

    - **App permissions**: **Read and write**. PostQueen does not need Direct Messages.
    - **Callback URI / Redirect URL**: the callback URL below.
    - **Website URL**: your public site.

    The form also asks for a type of app. That choice is for OAuth 2.0, which PostQueen does not use.

    If you change the permissions later, every X account that already connected has to reconnect: its token keeps the old permissions.
  </Step>
  <Step title="Register the callback URL">
    <OAuthRedirect />

    For X the host comes from `X_URL` when it is set, otherwise from `FRONTEND_URL`. PostQueen never wraps the X callback through `redirectmeto.com`, so a plain `http` address is registered as it is. X compares the URL exactly, trailing slash included, and takes up to 10 per app.

    <CodeGroup>

    ```text Your domain
    https://postqueen.example.com/integrations/social/x
    ```

    ```text Local development
    http://localhost:4200/integrations/social/x
    ```

    ```text Docker on your machine
    http://localhost:4007/integrations/social/x
    ```

    </CodeGroup>
  </Step>
  <Step title="Copy the Consumer Keys">
    If you did not save them when the app was created, open the app's keys and tokens and regenerate the **Consumer Keys**. The API Key goes in `X_API_KEY`, the API Key Secret in `X_API_SECRET`.
  </Step>
</Steps>

## Set the variables

Add the two keys to your environment:

```env
X_API_KEY="your api key"
X_API_SECRET="your api key secret"
```

Three optional variables change how X behaves:

| Variable | What it does |
|---|---|
| `X_URL` | Replaces `FRONTEND_URL` as the host of the callback. Leave it unset unless X must call back to a different address than the one people open. |
| `DISABLE_X_ANALYTICS` | Any value turns off X analytics and the two automations that read like counts (**Auto Repost Posts** and **Auto plug post**). That saves the credits those reads cost. |
| `STRIP_LINKS_FROM_X_POSTS` | Any value removes links from the text of every X post before it is published. |

<RestartAndAddChannel />

Pick **X**. PostQueen connects whichever X account is signed in on x.com in that browser, so switch accounts on X first if you want a different one. The **Long posts** setting, which raises the limit from 280 to 4,000 characters, is read from X when the account connects. Change it later in the channel's menu under **Publishing options**.

<Note>
With billing on (both `STRIPE_PUBLISHABLE_KEY` and `STRIPE_SECRET_KEY` set), a workspace still in its free trial cannot connect X until the trial ends. Without billing there is no trial, and no lock.
</Note>

## App review

X's getting-started docs describe no review for a pay-per-use app: once it has credits and the settings above, any X account can connect through it. What X does control is spending. When the credits run out or the spending limit is reached, X refuses the requests until you add credits.

X's own account limits still apply to every account that connects: unverified accounts can publish 50 posts and 200 replies a day across every app.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Callback URL not approved for this client application">
    The callback PostQueen sent is not in the app's list. Register `FRONTEND_URL` + `/integrations/social/x` exactly as in step 5, or the `X_URL` address if you set one.
  </Accordion>
  <Accordion title="X unlocks when your free trial ends. End the trial to connect it now.">
    Billing is on and the workspace is in its free trial. End the trial in the app, or wait for it to end.
  </Accordion>
  <Accordion title="There is a problem posting, please edit your post and check character count and media attachments">
    X refused the post. If every post fails this way, check that **App permissions** is **Read and write**, then reconnect the channel so its token carries the new permission.
  </Accordion>
  <Accordion title="Posting failed - capped reached. Please try again later">
    X capped the app's usage. Check the credit balance and the spending limit in the Developer Console.
  </Accordion>
  <Accordion title="X authentication has expired, please reconnect your account">
    X no longer accepts the account's token, for example after the app's permissions changed. Reconnect the channel.
  </Accordion>
</AccordionGroup>
