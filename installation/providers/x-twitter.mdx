On your own instance the X app is yours: create it in the X Developer Console, then put its consumer key and secret in your environment.

PostQueen connects X accounts with **OAuth 1.0a** (three-legged) and publishes through the X API v2. It reads only the app's **consumer key and secret** (`X_API_KEY`, `X_API_SECRET`). The OAuth 2.0 client id and secret, the bearer token and your own account's access token are not used; do not put them in those variables.

## Before you start

- **A developer account with credits.** The X API is pay-per-use: you buy credits in the [Developer Console](https://console.x.com) and each request is charged against them. At the time of writing, creating a post costs $0.015 and a post that contains a URL $0.20 ([X API pricing](https://docs.x.com/x-api/getting-started/pricing)). Connecting, publishing and PostQueen's analytics reads all use credits; set a spending limit in the console if you want a cap.

<Steps>
  <Step title="Create the app">
    Sign in to the [Developer Console](https://console.x.com) with the X account that will own the app, accept the Developer Agreement and create a new app.

    PostQueen does not need direct messages or email access, so do not request them.
  </Step>

  <Step title="Set up user authentication">
    Open the app's **User authentication settings** and set:

    1. **App permissions:** `Read and write`. With read-only access the connect can succeed and every post then fails.
    2. **Type of app:** `Native App`.
    3. **Callback URI / Redirect URL:** the address below.
    4. **Website URL:** your public website.

    <Warning>
    Select **Native App**. Setting the type to *Web App, Automated App or Bot* makes the OAuth 1.0a connect fail with error **32** (`Could not authenticate you`).
    </Warning>

    If you change the permission from read-only to read and write later, every account that already connected has to reconnect; its old token keeps the old permission.
  </Step>

  <Step title="Register the callback">
    <Snippet file="oauth2redirect.mdx" />

    For X the host part comes from `X_URL` when it is set, otherwise from `FRONTEND_URL`, and X matches the registered callback exactly.

    **Your X callback URL:**
    - Production: `https://postqueen.example.com/integrations/social/x`
    - Local development: `http://localhost:4200/integrations/social/x`
    - Docker: `http://localhost:4007/integrations/social/x`

    X answers `Callback URL not approved for this client application` (error 415) when the address PostQueen sends is not on the app's list.
  </Step>

  <Step title="Copy the consumer keys">
    Open **Keys and tokens**, then **Consumer Keys**, and click **Regenerate** to see the key and secret.

    | Console | Environment variable |
    | --- | --- |
    | API Key (consumer key) | `X_API_KEY` |
    | API Key Secret (consumer secret) | `X_API_SECRET` |

```env
X_API_KEY="your-consumer-key"
X_API_SECRET="your-consumer-secret"
```
  </Step>

  <Step title="Restart and add the X channel">
    <Snippet file="restart-and-add-channel.mdx" />

    PostQueen connects whichever X account is signed in on x.com in that browser, so switch accounts on X first if you want a different one. The **Verified** setting (4,000 characters instead of 280) is read from X at connect and can be changed later under the channel menu's **Additional Settings**.

    <Note>
    If your instance runs with Stripe billing enabled, a workspace still on its trial cannot connect X. Without billing there is no such lock.
    </Note>
  </Step>
</Steps>

## Optional environment variables

| Variable | What it does |
| --- | --- |
| `X_URL` | Replaces `FRONTEND_URL` as the host of the OAuth callback (`<X_URL>/integrations/social/x`). Leave it unset unless X must call back to a different address than the one users open; a wrong value breaks the connect. |
| `DISABLE_X_ANALYTICS` | Any value turns off X analytics and the automations that read like counts, which saves the credits those reads cost. |
| `STRIP_LINKS_FROM_X_POSTS` | Any value removes URLs from the text of every X post before it is published. |

Full list: [configuration reference](/configuration/reference).

## When something fails

| What you see | What to check |
| --- | --- |
| Error 32, `Could not authenticate you` | Type of app is not **Native App**, or the key and secret are not the consumer pair |
| Error 415 on connect | The callback registered on X differs from `<X_URL or FRONTEND_URL>/integrations/social/x` |
| 403 or "not permitted" on posting | App permission is read-only; set **Read and write**, then reconnect the channel |
| A usage-capped or 402 answer | The developer account has no credits left, or hit its spending limit |

See also [connect errors](/troubleshooting/common-errors).
