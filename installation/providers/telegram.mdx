On a self-hosted PostQueen the Telegram bot is yours. Telegram has no OAuth app and no redirect URI: you create a bot with BotFather, and a chat connects when someone adds the bot to it and sends a one-time `/connect` code there.

## Before you start

| | |
|---|---|
| Where | [@BotFather](https://t.me/BotFather) in any Telegram app |
| Variables | `TELEGRAM_TOKEN`, `TELEGRAM_BOT_NAME` |
| Redirect URI | None |
| Bot rights | In a channel, an administrator allowed to post messages. In a group, a member who can send messages and media |
| One bot per deployment | A bot token must not be shared with another PostQueen, or with anything else that reads the bot's updates |
| Review | None |

## Create the bot

<Steps>
  <Step title="Create the bot in BotFather">
    Open [@BotFather](https://t.me/BotFather) and send `/newbot`. Enter a display name, then a username that ends in `bot`, such as `acme_postqueen_bot`. A username is 5 to 32 characters of Latin letters, numbers and underscores.

    BotFather answers with the bot's token. Keep it private: anyone with it controls the bot. BotFather also has a Mini App with the same options, if you prefer buttons to commands.
  </Step>
  <Step title="Turn off group privacy">
    Send `/setprivacy` to BotFather, pick the bot and choose **Disable**.

    In a group, a bot with privacy mode on only receives commands that name it, such as `/start@acme_postqueen_bot`, and the `/connect` code PostQueen asks for does not name the bot. Administrators receive every message either way, and channels are not affected. If the bot is already in a group, remove it and add it again, because Telegram applies the change only when the bot joins.
  </Step>
</Steps>

## Set the variables

Add the token and the bot's username, without the `@`:

```env
TELEGRAM_TOKEN="123456789:your-bot-token"
TELEGRAM_BOT_NAME="acme_postqueen_bot"
```

Both are needed. The web app shows the username in the connect window, and the server uses the token to read the `/connect` code and to post.

## Connect a chat

<Steps>
  <Step title="Open Add Channel">
    Open **Channels**, choose **Add Channel**, then **Telegram**. The window names your bot: "Please add @acme_postqueen_bot to your telegram group / channel and click here:".
  </Step>
  <Step title="Add the bot to the chat">
    In Telegram, add the bot to the channel or group. A channel takes a bot only as an administrator, and it needs the right to post messages. In a group, make it an administrator if privacy mode is still on.
  </Step>
  <Step title="Send the /connect code">
    Back in PostQueen, choose **Connect Telegram**. The window shows a code such as `/connect a1B2`. Choose **Copy** and send it in the chat exactly as shown.
  </Step>
  <Step title="Check that it connected">
    The window checks every 2 seconds and connects the chat once the bot has read the code. If the bot is an administrator allowed to delete messages, it deletes your code and posts "Connection Successful. Message will be deleted in 10 seconds." Otherwise it says "Connection Successful. I don't have admin privileges to delete these messages, please go ahead and remove them yourself." The chat appears in the **Channels** list with its picture and name.
  </Step>
</Steps>

<Warning>
PostQueen reads the `/connect` code with Telegram's `getUpdates`, and Telegram allows one reader per bot. Two deployments on the same `TELEGRAM_TOKEN` consume each other's codes, and overlapping reads fail with `409 Conflict: terminated by other getUpdates request`. `getUpdates` also stops working while a webhook is set on the bot. Use one bot per deployment and never set a webhook on it.
</Warning>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Telegram is not set up on this installation">
    An admin sees "Telegram is not set up on this installation. Add TELEGRAM_TOKEN and TELEGRAM_BOT_NAME to the server environment and restart PostQueen." Other members see "Telegram is not set up on this installation yet. Ask a workspace admin to turn it on." `TELEGRAM_BOT_NAME` is empty: set both variables and recreate the container. An instance with billing turned on says "Telegram cannot be connected right now. Please contact support." for the same reason.
  </Accordion>
  <Accordion title="The window keeps waiting after the code was sent">
    The bot did not receive the code. In a group, privacy mode is still on and the bot is not an administrator: disable it with `/setprivacy`, then remove the bot and add it again. In a channel, the bot is not an administrator. Send the code exactly as shown, without `@` and the bot's name after `/connect`. If none of that helps, check that no other deployment uses the same token and that the bot has no webhook.
  </Accordion>
  <Accordion title="409 Conflict: terminated by other getUpdates request">
    Another process reads the same bot's updates. Give each PostQueen deployment its own bot.
  </Accordion>
  <Accordion title="Posts to a channel fail">
    The bot is not an administrator of the channel, or it lost the right to post messages. Make it an administrator with that right.
  </Accordion>
</AccordionGroup>
