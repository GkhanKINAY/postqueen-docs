On your own instance the Google Cloud project is yours: create one **web** OAuth client, enable the YouTube APIs, then put the client id and secret in your environment.

<Warning>
**This same client is Google sign-in.** When `IS_GENERAL` is set (the shipped compose default), the **Continue with Google** button on `/auth` reads `YOUTUBE_CLIENT_ID` and `YOUTUBE_CLIENT_SECRET`. There is no separate Google-login client. Do not create a second OAuth app for sign-in: login and YouTube connect share this one, and Google My Business can fall back to it as well.

Login asks Google only for `userinfo.profile` and `userinfo.email`. Connecting a YouTube channel asks for those plus the six YouTube scopes below, with `access_type=offline` so she can keep a refresh token.
</Warning>

Google's current console names this **Google Auth Platform** (Branding, Audience, Clients, Data Access). Older docs still say **APIs & Services → Credentials**; the values are the same.

Follow Google's [Obtaining authorization credentials](https://developers.google.com/youtube/registering_an_application) alongside the steps here.

## General Setup

<Steps>
  <Step title="Open Google Cloud">
    Sign in and open [Google Auth Platform](https://console.cloud.google.com/auth/overview) (or [APIs & Services → Credentials](https://console.cloud.google.com/projectselector2/apis/credentials)). Accept the terms if asked.
  </Step>

  <Step title="Create or select a project">
    Create a project, or pick the one you already use for PostQueen. Fill in the name and click **Create**.
  </Step>

  <Step title="Enable the YouTube APIs">
    **Enabled APIs and Services** → **Enable APIs and Services**. Search for each of these and click **Enable**:

    - YouTube Data API v3
    - YouTube Analytics API
    - YouTube Reporting API

    <Frame>
      <img src="/images/providers/youtube/YouTube-Enabled-APIs.png" alt="The Enabled APIs and Services page in Google Cloud Console" />
    </Frame>

    <Frame>
      <img src="/images/providers/youtube/Enable-APIs-and-Services.png" alt="The API library search results, with YouTube Data API v3 ready to enable" />
    </Frame>
  </Step>

  <Step title="Configure the consent screen (Branding, Audience, Data Access)">
    User type **External**, unless you have a Google Workspace organization and want Internal.

    Fill in the app name, support email, homepage, privacy policy and terms. Add your public hostname (for example `postqueen.example.com`) as an authorized domain.

    For a public install Google will also check **branding**: the homepage must be a Search Console-verified property on that domain, and the logo must uniquely identify the product (a generic icon is rejected). Branding verification is separate from YouTube scope verification. You can publish first and finish branding afterwards; until branding is accepted, Google may still show its own placeholder instead of your name and logo.

    On **Data Access** (older wizards: the Scopes step), add all eight. Connecting a YouTube channel is refused if any one is missing:

    ```
    https://www.googleapis.com/auth/userinfo.profile
    https://www.googleapis.com/auth/userinfo.email
    https://www.googleapis.com/auth/youtube
    https://www.googleapis.com/auth/youtube.force-ssl
    https://www.googleapis.com/auth/youtube.readonly
    https://www.googleapis.com/auth/youtube.upload
    https://www.googleapis.com/auth/youtubepartner
    https://www.googleapis.com/auth/yt-analytics.readonly
    ```

    Save until the Save / Discard bar is gone. `openid` appears on its own with the userinfo scopes; you do not have to add it.

    Add **your own Google account** as a test user. It has to be a real Google login, not a made-up address.

    <Frame>
      <img src="/images/providers/youtube/YouTube-Add-Test-Users.png" alt="The OAuth consent screen test users panel, with the control for adding your own account" />
    </Frame>

    <Warning>
    While the app is in **Testing**, only those test users can sign in with Google or connect YouTube. Everyone else sees Google's access-denied screen.

    **Audience → Publish app** is what you do for a public install. Google *will* let an External app leave Testing before YouTube verification is finished. After that:

    - **Continue with Google** (non-sensitive `userinfo` scopes) works for any Google account.
    - Connecting a YouTube channel still requests the **sensitive** scopes. Until you complete [Data Access verification](https://console.cloud.google.com/auth/verification) (justifications plus a demo video), those users see Google's unverified-app screen, and Google keeps the 100-user cap on those scopes.

    You do not have to stay in Testing for login to work. Stay in Testing only if you want to keep the install private. Brand accounts on a Workspace can stay unpublished if you trust the app in the admin console; see below.
    </Warning>
  </Step>

  <Step title="Create a Web application OAuth client">
    **Clients** → **Create client** → application type **Web application**.

    <OAuthRedirect />

    For this Google client you usually need **more than one** redirect URI, because login, YouTube and (if you share the client) Google My Business all come back to different paths. No trailing slash. A mismatch, including a trailing slash, fails as `invalid_grant`.

    **Authorized JavaScript origins** (your `FRONTEND_URL`, no path):

    - Production: `https://postqueen.example.com`
    - Local Next: `http://localhost:4200`
    - Docker frontend: `http://localhost:4007`

    If the product is on a subdomain (`https://app.postqueen.example.com`) and the branding homepage is the apex, list **both**.

    **Authorized redirect URIs:**

    - Production: `https://postqueen.example.com/integrations/social/youtube`
    - Local Next: `http://localhost:4200/integrations/social/youtube`
    - Docker: `http://localhost:4007/integrations/social/youtube`

    If this client will also handle Google My Business (PostQueen falls back to `YOUTUBE_CLIENT_*` when `GOOGLE_GMB_*` is empty), add the matching `/integrations/social/gmb` URIs too. You still have to put `business.manage` on Data Access and enable the Business Profile APIs; that is the [GMB guide](/installation/providers/google-my-business).

    <Frame>
      <img src="/images/providers/youtube/youtube-001.png" alt="The OAuth client configuration in Google Cloud Console, with the Authorized redirect URIs field" />
    </Frame>

    Copy the client ID and secret **from the create dialog**. Google will not show the secret again; the console only keeps the last four characters. A mistyped secret still lets Google show the consent screen (that step uses the client id alone), then PostQueen's `/auth/oauth/GOOGLE/exists` call fails with `invalid_client` and the login page spins. If that happens, on the same web client click **Add secret**, put the new value in env, recreate the container, and disable the old secret once login works. Do not create a second OAuth client.

```env
YOUTUBE_CLIENT_ID=""
YOUTUBE_CLIENT_SECRET=""
```

    Recreate the PostQueen container after you save the file. A plain `docker restart` keeps the old environment.
  </Step>

  <Step title="Restart and add the YouTube channel">
    <RestartAndAddChannel />
  </Step>
</Steps>

Sign in with Google uses the same keys. After the restart, `/auth` → **Continue with Google** should send you to `accounts.google.com` with this client id. YouTube connect is **Add Channel** → YouTube, then pick the channel on the second step.

## Additional Steps for Brand Accounts

<Info>
When using a Brand account you will need to set your app to External and add a test user. You do not need to publish the app, but it does take time for the changes to propagate. You will also need to add the app to the trusted apps within your Google Workspace Admin.
</Info>

<Steps>
  <Step title="Go to admin.google.com">
    Sign in
  </Step>

  <Step title="Go to Security Settings">
    Go to Security → Access and data Controls → API Controls
    Click Manage Third Party App Access
  </Step>

  <Step title="Configure new App">
    Click "Configure new App"
    Put your Client ID for the app you created in previous steps into the search box and select your app
  </Step>

  <Step title="Set scopes and Google Data Access">
    Set scopes and Google Data Access for the app to Trusted
    Once set, click save
  </Step>

  <Step title="Wait for propagation">
    Wait at least 5 hours for the changes to propagate.
    After this time you should now be able to add your YouTube channel to your PostQueen account
  </Step>
</Steps>
