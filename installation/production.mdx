This walkthrough takes an empty virtual machine to PostQueen running at `https://postqueen.example.com`. Every command is written out. Plan on about thirty minutes, most of it downloads.

## What you need

| | |
|---|---|
| A server | A Linux virtual machine with Ubuntu 24.04, 2 vCPU and at least 4 GB of memory. [Self-hosting overview](/installation/overview#what-the-machine-needs) has the sizing. |
| A domain | A domain or subdomain whose DNS you control. A certificate needs a name, so an IP address alone is not enough. |
| A terminal | With SSH, on your own computer. |

Replace `postqueen.example.com` with your own name everywhere on this page.

## Install

<Steps>
  <Step title="Create the server">
    Order an Ubuntu 24.04 machine from any provider. Note its public IP address, for example `203.0.113.42`, and the SSH login it gives you.
  </Step>
  <Step title="Point the domain at it">
    Where your domain's DNS is managed, add an **A record**: name `postqueen` (or `@` for the bare domain), value the server's IP address. Then check from your own computer:

    ```bash
    dig +short postqueen.example.com
    ```

    <Check>
    The command prints the server's IP address. The certificate step fails until it does.
    </Check>
  </Step>
  <Step title="Connect and install Docker">
    ```bash
    ssh root@203.0.113.42
    curl -fsSL https://get.docker.com | sh
    docker compose version
    ```

    Use the username your provider gave you if it is not `root`. The last command prints the Compose version, which has to be v2.24 or newer. Every command from here runs on the server.
  </Step>
  <Step title="Open only SSH and the web ports">
    ```bash
    ufw allow OpenSSH
    ufw allow 80/tcp
    ufw allow 443/tcp
    ufw --force enable
    ```

    <Warning>
    Allow `OpenSSH` before you enable the firewall, or it locks you out of the server.
    </Warning>
  </Step>
  <Step title="Clone the Compose repository">
    ```bash
    git clone https://github.com/GkhanKINAY/postqueen-docker-compose
    cd postqueen-docker-compose
    ```

    Stay in this folder. It holds `docker-compose.yaml` and the `dynamicconfig` folder Temporal reads at start.
  </Step>
  <Step title="Bind port 4007 to the server itself">
    Docker publishes container ports past UFW, so the rules above do not close port 4007. In `docker-compose.yaml`, change the `postqueen` service's port line:

    ```yaml
    ports:
      - "127.0.0.1:4007:5000"
    ```

    PostQueen then answers only on the server, where the reverse proxy reaches it, and the outside world sees only ports 80 and 443. Keeping the original `"4007:5000"` leaves PostQueen reachable over plain HTTP on port 4007 from anywhere.
  </Step>
  <Step title="Write the .env file">
    ```bash
    printf 'JWT_SECRET=%s\nENCRYPTION_KEY=%s\nMAIN_URL=%s\nFRONTEND_URL=%s\nNEXT_PUBLIC_BACKEND_URL=%s\n' \
      "$(openssl rand -hex 32)" "$(openssl rand -hex 32)" \
      https://postqueen.example.com https://postqueen.example.com https://postqueen.example.com/api > .env
    ```

    Put your own domain in the three addresses before you run it. Keep `/api` on the last one and leave off trailing slashes. Do **not** add `NOT_SECURED`: the site runs on HTTPS.

    <Warning>
    **Keep both keys once set.** `JWT_SECRET` signs sessions, so changing it signs everyone out. `ENCRYPTION_KEY` encrypts the API key, the stored credentials of networks such as Bluesky and WordPress, and other secrets, so changing it without `PREVIOUS_ENCRYPTION_KEY` makes those unreadable. Setting `ENCRYPTION_KEY` now, before there is data, is what lets you rotate `JWT_SECRET` later. See [Configuration reference](/configuration/reference#encryption-key).
    </Warning>
  </Step>
  <Step title="Pin the image">
    The Compose file uses `ghcr.io/gkhankinay/postqueen-app:latest`, which moves with every release. Pin a release tag so an upgrade happens when you choose:

    ```yaml
    image: ghcr.io/gkhankinay/postqueen-app:vX.Y.Z
    ```

    Take the newest tag from the [app's tags](https://github.com/GkhanKINAY/postqueen-app/tags) or the [image package](https://github.com/GkhanKINAY/postqueen-app/pkgs/container/postqueen-app), written with its `v`. The GitHub Releases page is not kept current, so do not take the version from there. Later, only ever move the tag forward: [Backups and upgrades](/installation/backups-and-upgrades) explains why.
  </Step>
  <Step title="Start PostQueen">
    ```bash
    docker compose up -d
    docker compose logs -f postqueen
    ```

    Wait for `Backend started successfully on port 3000`, then press `Ctrl+C`. Read the lines just after it: the backend checks its settings and prints each problem as a `Configuration issue`, but keeps running either way. Then check that it answers on the server:

    ```bash
    curl -I http://localhost:4007
    ```

    <Check>
    `HTTP/1.1 200 OK`.
    </Check>
  </Step>
  <Step title="Add HTTPS">
    Put a reverse proxy in front of port 4007. With Caddy it is three lines and the certificate renews itself: follow [Domain and HTTPS](/installation/domain-and-https#set-up-caddy), then come back when `https://postqueen.example.com` loads.

    [Nginx](/reverse-proxies/nginx) and [Traefik](/reverse-proxies/traefik) work too.
  </Step>
  <Step title="Create your account, then close sign-up">
    Open `https://postqueen.example.com` and sign up. That first account owns the install.

    Everyone who should have an account on this install has to sign up now, before you close it. Then add this line to `.env`:

    ```env
    DISABLE_REGISTRATION=true
    ```

    <RestartService />

    <Note>
    **Closing sign-up also blocks invitations for new people.** Existing accounts sign in as before, and you can still invite someone who already has an account here. A person without one cannot create it from an invite while this is set. People who sign in through your own [single sign-on](/configuration/oauth) provider are the exception: they still get an account.
    </Note>
  </Step>
</Steps>

<Check>
PostQueen runs on your domain, over HTTPS, and nobody new can sign up.
</Check>

## Connect channels

Eight networks connect with a key or login in the connect form and need no setup: Bluesky, DEV, Hashnode, Lemmy, Listmonk, Moltbook, Nostr and WordPress. For the others, register a developer app with the network, put its keys in `.env`, recreate the `postqueen` container, then open **Channels** and choose **Add Channel**. [Channel developer apps](/installation/providers/overview) lists each network's variables, redirect URI and setup page.

## If something is not right

<AccordionGroup>
  <Accordion title="The site does not load">
    Work outward from the container. If `curl -I http://localhost:4007` fails on the server, PostQueen is not up: `docker compose logs postqueen` says why. If it works but the domain does not, check DNS with `dig +short postqueen.example.com` and the proxy's own log.
  </Accordion>
  <Accordion title="Sign-in fails or does not stick">
    `FRONTEND_URL` has to be exactly the address in the browser, with `https://` and no trailing slash. The backend accepts requests only from that address and `MAIN_URL`. Look for the backend's warnings:

    ```bash
    docker compose logs postqueen | grep -i "configuration issue"
    ```

    Do not set `NOT_SECURED=true` to work around it on a public server.
  </Accordion>
  <Accordion title="Connecting a channel fails at the network">
    Each network sends the browser back to `FRONTEND_URL` + `/integrations/social/` + the network's name. If `FRONTEND_URL` changed after you registered the app, update the redirect URI in the network's console. A missing or wrong key shows up as an error page on the network's side, not in PostQueen.
  </Accordion>
  <Accordion title="Containers restart in a loop">
    Usually memory. `docker stats` shows usage, and `docker compose logs postqueen` shows why it stopped. The stack needs about 4 GB.
  </Accordion>
  <Accordion title="Everyone was signed out after a restart">
    `JWT_SECRET` changed. Put the old value back, or accept that everyone signs in again. [Self-hosting troubleshooting](/troubleshooting/self-host) covers what else a changed key breaks.
  </Accordion>
</AccordionGroup>
