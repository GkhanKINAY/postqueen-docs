Recreate the app container so it reads the new variables. A plain `docker restart` or
`docker compose restart` keeps the old container and its old environment.

In the folder that holds `docker-compose.yaml`, recreate only the `postqueen` service:

```bash
docker compose up -d --no-deps --force-recreate postqueen
```

The database, Redis and Temporal keep running. Avoid `docker compose down` for a settings change: on
a host that runs other Compose services in the same project, it stops them too.

Then open PostQueen, go to **Channels**, choose **Add Channel** and pick this network. You are
sent to its login to authorize PostQueen, and the channel appears in your channel list once you
accept.

<Check>
The channel is in your channel list with its avatar and name. That is the whole confirmation: if it
is in the list, PostQueen can post to it.
</Check>

<Note>
**Add Channel does not check whether your variables are set.** A missing or misspelled key shows
up as a broken authorization page on the network's side rather than a helpful message in
PostQueen, so if the login page itself looks wrong, check the keys before anything else.
</Note>
