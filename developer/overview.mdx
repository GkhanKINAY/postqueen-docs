Whether you are scripting a week of posts from a shell, shipping a product other people log into,
or handing the whole job to an assistant, you are talking to the same calendar. Pick the route that
matches how you already work.

## Choose your path

<CardGroup cols={2}>
  <Card title="Command line" icon="terminal" href="/cli/introduction">
    `npm install -g postqueen`, export your key, and sixteen commands are one line away. Prints
    JSON, so a CI job can read the answer.

    **Best for:** shells, cron, CI, and coding agents.
  </Card>
  <Card title="Node SDK" icon="cube" href="/public-api/sdk">
    `@postqueen/node` is a typed client where every method maps to one endpoint, so your editor
    tells you the shape before you run it.

    **Best for:** TypeScript and Node services.
  </Card>
  <Card title="REST API" icon="code" href="/public-api/introduction">
    Twenty-two key-authenticated operations, plus the two OAuth2 endpoints. The widest surface
    here, and the layer the other three ride on.

    **Best for:** any language, and anything the others cannot reach.
  </Card>
  <Card title="MCP" icon="network-wired" href="/mcp/introduction">
    One URL, and eleven tools arrive in Claude, ChatGPT or Cursor with their schemas attached.
    Nothing to install for most clients.

    **Best for:** describing the post instead of writing the call.
  </Card>
</CardGroup>

## What every route shares

<Info>
**One API key.** Create it in the app under Settings, then send it in the `Authorization` header
with no `Bearer` prefix. The CLI reads it from `POSTQUEEN_API_KEY`, and the n8n credential stores
it for you.
</Info>

Three things hold no matter which door you came through:

| | |
|---|---|
| **The same calendar** | All four sit on the public API, so a post lands in one place and goes out at the time you set, whichever route created it |
| **The same rate limit** | The create-post endpoint is capped per organization per hour by a single instance-wide `API_LIMIT`, identical on every plan. Cloud and the shipped Compose files set it to 30; unset on your own instance it sits at 90 |
| **The same gaps** | Nothing routes around a platform's own rules. If X refuses a post, every interface reports the same refusal |

<Warning>
The CLI reaches **thirteen** of the API's twenty-two endpoints, and MCP carries no analytics and
cannot list or delete an existing post. Read [Limits and Gaps](/cli/limits) and
[MCP limits](/mcp/limits-and-troubleshooting) before you build a pipeline on either, not halfway
through.
</Warning>

## Building for other people

If your users are PostQueen users, do not ask them for an API key.
[OAuth2](/public-api/oauth) issues tokens that act on their behalf, and those tokens start with
`pos_`.

Writing a connector for a network we do not carry yet is a different job, and it happens inside the
app rather than against the API: [Create a provider](/configuration/create-provider).
