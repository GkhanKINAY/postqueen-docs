Every request carries the same five fields: `type`, `date`, `shortLink`, `tags` and `posts`. Each entry in `posts` is one channel, and each item in its `value` list is one part of the post: the first is the post, the rest are its thread or comments.

```json
{
  "type": "schedule",
  "date": "2026-10-01T09:00:00.000Z",
  "shortLink": false,
  "tags": [],
  "posts": [
    {
      "integration": { "id": "YOUR_CHANNEL_ID" },
      "value": [{ "content": "Shipping the new calendar today.", "image": [] }]
    }
  ]
}
```

A step-by-step guide, from finding the channel id to checking the result, is [Schedule a post with the API](/public-api/schedule-a-post).

## `type`

| Value | What happens |
|---|---|
| `schedule` | The post goes out at `date`, in UTC. |
| `now` | The post goes out at once. `date` is still required, and PostQueen stamps the current minute instead. |
| `draft` | Saved on the channel's calendar without publishing. Move it to scheduled later with [Change post status](/public-api/posts/change-status). |
| `update` | Changes existing posts in place, named by `value[].id`, without starting a new publish. |

<Note>
A draft is checked too: the body, and each network's required settings. The network's rules on length and media are checked only when the post is set to go out (`schedule`, `now` and `update`). So a draft you schedule later is already complete.
</Note>

## The request

| Field | Required | What it does |
|---|---|---|
| `type` | Yes | `schedule`, `now`, `draft` or `update`, as above |
| `date` | Yes | When the post goes out, in UTC, ISO 8601 |
| `shortLink` | Yes | `true` replaces links with PostQueen short links. Send `false` to keep them as they are |
| `tags` | Yes | Tags to attach, as `{ value, label }`. PostQueen attaches only tags that already exist in the workspace. Send `[]` for none |
| `posts` | Yes | One entry per channel, described below |
| `inter` | No | Repeat the post every this many days |
| `republish` | No | `true` to publish again a post that was already published |

Each entry in `posts`:

| Field | Required | What it does |
|---|---|---|
| `integration.id` | Yes | The channel, from [List channels](/public-api/integrations/list) |
| `value` | Yes | The post, then its thread or comments. Each item has `content`, `image`, and optionally `delay` and `id` |
| `value[].content` | Yes | The text. It may be empty only when the item has media |
| `value[].image` | Yes | Media, as `{ id, path }` from an upload. Send `[]` for text only |
| `value[].delay` | No | Minutes to wait after the previous item of a thread |
| `value[].id` | No | An existing post's id, to change that post in place |
| `settings` | Depends on the network | The network's settings: see the table below |
| `group` | No | Leave it out for a new post. With an existing group, every post of that group you do not resend is deleted |

Media must be uploaded first. A post's media path must end in `.png`, `.jpg`, `.jpeg`, `.gif`, `.webp` or `.mp4`, and a video must be `ready`: see [Upload a file](/public-api/uploads/upload-file).

## Settings by network

`settings.__type` is always set from the channel, so you may leave it out; what matters is the shape of the rest. Networks without required settings need no `settings` at all. Every field of every network, with examples: [Posting settings by network](/public-api/providers/overview).

| Network | Required settings | On PostQueen |
|---|---|---|
| Bluesky, Nostr | None | Available |
| WordPress | `title`, `type` (`posts`, `pages` or another post type from the `postTypes` tool) | Available |
| DEV | `title` | Available |
| Hashnode | `title`, `publication`, at least one `tags` entry | Available |
| Lemmy | `subreddit` list, each with a community and a title | Available |
| Listmonk | `subject`, `preview`, `list` | Available |
| Moltbook | `submolt` | Available |
| X | `who_can_reply_post`, or `article_title` and `article_status` for an article | In review |
| Instagram | `post_type` | In review |
| YouTube | `title`, `type` | In review |
| TikTok | Eight fields, from `privacy_level` to `content_posting_method`: see [TikTok settings](/public-api/providers/tiktok) | In review |
| Facebook, Threads | None | In review |
| Reddit | `subreddit` list, each with a subreddit, title, type and flair choice | Soon |
| Pinterest | `board` | Soon |
| Dribbble | `title` | Soon |
| Discord, Slack | `channel` | Soon |
| Skool | `group`, `label`, `title` | Soon |
| Whop | `company`, `experience` | Soon |
| MeWe | `postType`, and `group` for a group post | Soon |
| Farcaster | `subreddit` list of channels | Soon |
| Google Business Profile | None; an event or offer needs `eventTitle`, `eventStartDate` and `eventEndDate` | Soon |
| LinkedIn, Mastodon, Telegram, VK, Kick, Twitch, Tumblr | None | Soon |

What **In review** and **Soon** mean for each network is on [Channels](/channels/overview).

## What comes back

A `201` with one row per channel entry. Keep the `postId`s: the other post endpoints take them.

```json
[{ "postId": "cmg1p0s7k0001qz0h4yq2a8r1", "integration": "cmg1ozx2c0000qz0h8c7w5v3n" }]
```

When a part breaks a network's rule, the call answers `400` before anything is saved, naming the network and the channel:

```json
{
  "statusCode": 400,
  "provider": "bluesky",
  "name": "PostQueen",
  "message": "post is too long, please fix it"
}
```

Every status the endpoint returns, and what to do about it, is on [Limits and errors](/public-api/limits-and-errors).

## Changing or copying a post

- **Change a scheduled post.** Send it again with `value[].id` set to the id of each part you keep, and its `group` from [List posts](/public-api/posts/list) so the parts you leave out are deleted. Use `update` with the post's current `date` to change its text or media without touching the schedule, or `schedule` with a new `date` to move it. To change only its settings, [Update post settings](/public-api/posts/settings) is simpler.
- **Publish a post again.** `schedule` or `now` with the id of a post that was already published is refused with `400`. Add `"republish": true` if you mean it.
- **Copy a post.** There is no copy endpoint. Read the post with [List posts](/public-api/posts/list), parse its `settings` and `image` (they come back as JSON strings), and send the content as a new post without any post ids or `group`.

## Body size

<Warning>
Do not put file data in the body. This endpoint takes about 100 kB of JSON, which one base64 image exceeds, and answers `413` before anything is checked. Upload the file first and send its `id` and `path`.
</Warning>

<Note>
`POST /posts` has an hourly limit per workspace. One request can carry many channels and a whole thread, and it counts once. See [Limits and errors](/public-api/limits-and-errors).
</Note>
