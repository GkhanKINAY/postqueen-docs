Every post to DEV carries a `settings` object with `"__type": "devto"` and a title. Read the live schema for your channel with [Get a channel's settings](/public-api/integrations/settings).

A DEV channel connects with a DEV API key, which only the app's connect form takes. [Connect it in the app](/channels/devto) first, then post to it here.

## Fields

| Field | Type | Required | What it does |
|---|---|---|---|
| `__type` | string | No | Always `"devto"`. PostQueen sets it from the channel you post to, so it can be left out. |
| `title` | string | Yes | The article title, 2 to 128 characters. |
| `main_image` | object | No | The cover image, `{ "id": "...", "path": "..." }` as [upload a file](/public-api/uploads/upload-file) returns it. |
| `canonical` | string | No | Where the article first appeared, as a web address. |
| `organization` | string | No | The id of a DEV organization to publish under, from the `organizations` tool. |
| `tags` | array | No | Up to 4 tags, each `{ "value": 123, "label": "javascript" }` from the `tags` tool. DEV is sent the `label`. |

The body comes from `value[0].content` as Markdown. The article is always published, never saved as a DEV draft. DEV has no follow-ups, so entries after the first in `value` are not published, and media in `value` is not sent: only `main_image` reaches DEV.

### Find tags and organizations

Two tools read them from DEV. Call them through [trigger a provider tool](/public-api/integrations/trigger), with no data:

```bash
curl -X POST "{{apiBase}}/integration-trigger/YOUR_CHANNEL_ID" \
  -H "Authorization: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"methodName": "tags", "data": {}}'
```

| Tool | Answers | Use it for |
|---|---|---|
| `tags` | `[{ "value": 6, "label": "javascript" }, ...]` | `tags`: send the objects as they are |
| `organizations` | `[{ "id": 1234, "name": "...", "username": "..." }, ...]` | `organization`: send the `id` as a string |

`organizations` lists only organizations the account has already published an article for. Each answer comes wrapped in `{ "output": ... }`.

## What PostQueen checks

A post that breaks one of these rules is refused with `400` before it is scheduled:

| Rule | Message |
|---|---|
| A title of at least 2 characters | “title must be longer than or equal to 2 characters” |
| A title of at most 128 characters, as DEV allows | “title must be shorter than or equal to 128 characters” |
| At most 4 tags | “tags must contain no more than 4 elements” |
| Each tag's `value` is a number | “value must be a number conforming to the specified constraints” |
| `canonical` is a web address | “Invalid URL” |
| The body within 100,000 characters | “post is too long, please fix it” |

The settings rules come back as a list, with each field's path:

```json
{
  "statusCode": 400,
  "message": ["posts.0.settings.title must be shorter than or equal to 128 characters"],
  "error": "Bad Request"
}
```

The text limit comes back with the channel's name instead, as on [posting settings by network](/public-api/providers/overview#two-error-shapes).

DEV's own rules are not checked first. A canonical URL that another of your articles already uses is refused when the article is published, with “Canonical URL already exists”.

## Examples

Send each body to [create a post](/public-api/posts/create). Replace `YOUR_CHANNEL_ID` with the channel's id from [list channels](/public-api/integrations/list), the tags and organization with values from the tools above, and the media `id` and `path` with the values [upload a file](/public-api/uploads/upload-file) returns.

<CodeGroup>

```json Article with tags and a cover
{
  "type": "schedule",
  "date": "2026-10-01T09:00:00.000Z",
  "shortLink": false,
  "tags": [],
  "posts": [
    {
      "integration": { "id": "YOUR_CHANNEL_ID" },
      "value": [
        {
          "content": "## Why we moved to Postgres\n\nWe ran on a document store for three years. Here is what changed when we switched.",
          "image": []
        }
      ],
      "settings": {
        "__type": "devto",
        "title": "What we learned moving to Postgres",
        "main_image": { "id": "MEDIA_ID", "path": "https://uploads.postqueen.ai/postgres-cover.png" },
        "canonical": "https://example.com/blog/moving-to-postgres",
        "tags": [
          { "value": 6, "label": "javascript" },
          { "value": 1234, "label": "postgres" }
        ]
      }
    }
  ]
}
```

```json Under an organization
{
  "type": "schedule",
  "date": "2026-10-01T09:00:00.000Z",
  "shortLink": false,
  "tags": [],
  "posts": [
    {
      "integration": { "id": "YOUR_CHANNEL_ID" },
      "value": [
        { "content": "Our team's notes from this year's conference, talk by talk.", "image": [] }
      ],
      "settings": {
        "__type": "devto",
        "title": "Conference notes",
        "organization": "1234"
      }
    }
  ]
}
```

</CodeGroup>
