Every post to Mastodon carries a `settings` object with `"__type": "mastodon"`, and nothing else: Mastodon has no settings of its own. Read the live schema for your channel with [Get a channel's settings](/public-api/integrations/settings).

## Fields

| Field | Type | Required | What it does |
|---|---|---|---|
| `__type` | string | No | Always `"mastodon"`. PostQueen sets it from the channel you post to, so it can be left out. |

Every post is public. Alt text goes on each file in `image`, as `alt`, and PostQueen sends it to Mastodon as the file's description.

## What PostQueen checks

A post that breaks this rule is refused with `400` before it is scheduled:

| Rule | Message |
|---|---|
| Each entry up to 500 characters | “post is too long, please fix it” |

The error body names the channel and the rule:

```json
{
  "statusCode": 400,
  "provider": "mastodon",
  "name": "Your channel name",
  "message": "post is too long, please fix it"
}
```

The server's own rules are not checked first: how many files a post can carry, usually 4 images or 1 video, and the largest video it accepts. PostQueen waits until the server has processed a video before it creates the first post. Files in later thread parts are posted without that wait, so a part with a large video can fail.

## Examples

Send each body to [create a post](/public-api/posts/create). Replace `YOUR_CHANNEL_ID` with the channel's id from [list channels](/public-api/integrations/list), and each media `id` and `path` with the values [upload a file](/public-api/uploads/upload-file) returns.

<CodeGroup>

```json Text post
{
  "type": "schedule",
  "date": "2026-10-01T09:00:00.000Z",
  "shortLink": false,
  "tags": [],
  "posts": [
    {
      "integration": { "id": "YOUR_CHANNEL_ID" },
      "value": [
        {
          "content": "Version 2.4 is out: faster search, dark mode, and a fix for the export bug many of you reported.",
          "image": []
        }
      ],
      "settings": { "__type": "mastodon" }
    }
  ]
}
```

```json Thread with an image
{
  "type": "schedule",
  "date": "2026-10-01T09:00:00.000Z",
  "shortLink": false,
  "tags": [],
  "posts": [
    {
      "integration": { "id": "YOUR_CHANNEL_ID" },
      "value": [
        {
          "content": "Three things we changed in the new dashboard. A thread.",
          "image": [
            {
              "id": "MEDIA_ID",
              "path": "https://uploads.postqueen.ai/dashboard.png",
              "alt": "The new dashboard, with the calendar on the left and the post list on the right"
            }
          ]
        },
        {
          "content": "1. Search now covers drafts as well as published posts.",
          "image": [],
          "delay": 2
        },
        {
          "content": "2. The calendar remembers the view you used last.",
          "image": [],
          "delay": 2
        }
      ],
      "settings": { "__type": "mastodon" }
    }
  ]
}
```

```json Video post
{
  "type": "schedule",
  "date": "2026-10-01T09:00:00.000Z",
  "shortLink": false,
  "tags": [],
  "posts": [
    {
      "integration": { "id": "YOUR_CHANNEL_ID" },
      "value": [
        {
          "content": "A one-minute tour of the new dashboard.",
          "image": [
            {
              "id": "MEDIA_ID",
              "path": "https://uploads.postqueen.ai/tour.mp4",
              "alt": "Screen recording of the dashboard tour"
            }
          ]
        }
      ],
      "settings": { "__type": "mastodon" }
    }
  ]
}
```

</CodeGroup>

In the thread example, each entry after the first in `value` is posted as a reply to the one before, 2 minutes apart.
