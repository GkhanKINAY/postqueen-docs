[`@postqueen/node`](https://www.npmjs.com/package/@postqueen/node) is a small typed client for the [PostQueen API](/public-api/introduction). It sends your API key and calls five endpoints for you: list channels, create a post, list posts, upload a file and delete a post. Everything else in the API is a plain HTTPS call, shown [below](#calls-the-sdk-does-not-wrap).

This page describes version 1.0.4. Run `npm ls @postqueen/node` to see yours.

## Before you start

- **Node.js 20.19 or newer.** On Node.js 22, use 22.12 or newer. The package loads its HTTP library with `require`, which older versions refuse.
- **A PostQueen workspace on a trial or a paid plan**, with at least one connected channel.
- **The API key**, from the box below.

## Install and schedule a first post

<Steps>
  <Step title="Install the package">
    <CodeGroup>

    ```bash npm
    npm install @postqueen/node
    ```

    ```bash pnpm
    pnpm add @postqueen/node
    ```

    </CodeGroup>
  </Step>
  <Step title="Set your key">
    ```bash
    export POSTQUEEN_API_KEY=your_api_key
    ```

    The client takes the key as its first argument. Reading it from the environment keeps it out of your code.
  </Step>
  <Step title="Schedule a post">
    This finds your Bluesky channel and schedules a text post on it.

    ```typescript schedule.ts
    import PostQueen from '@postqueen/node';

    type Channel = { id: string; name: string; identifier: string; disabled: boolean };

    async function main() {
      const postqueen = new PostQueen(process.env.POSTQUEEN_API_KEY!);

      // The channels you can post to. The API calls them integrations.
      const channels = (await postqueen.integrations()) as Channel[];
      const bluesky = channels.find((c) => c.identifier === 'bluesky');
      if (!bluesky) throw new Error('Connect a Bluesky channel first');

      // Schedule a text post
      const created = await postqueen.post({
        type: 'schedule',
        date: '2026-10-01T09:00:00.000Z',
        shortLink: false,
        tags: [],
        posts: [
          {
            integration: { id: bluesky.id },
            group: '',
            settings: { __type: 'bluesky' },
            value: [{ id: '', content: 'Shipping the new calendar today.', image: [], delay: 0 }],
          },
        ],
      });
      console.log(created); // [{ postId, integration }]
    }

    main();
    ```
  </Step>
  <Step title="Check it">
    The post appears on the calendar in the app, and `created` holds one `{ postId, integration }` per channel.
  </Step>
</Steps>

<Note>
`group: ''`, `id: ''` and `delay: 0` are there because the 1.0.4 types require them, not because the API does. The next section explains each one.
</Note>

### In an ES module

In a CommonJS project, or in TypeScript compiled to CommonJS with `esModuleInterop`, the default import above works. In an ES module (`"type": "module"`, a `.mjs` file, or TypeScript with `"module": "nodenext"`), the class is on `.default`:

```typescript
import pkg from '@postqueen/node';

const PostQueen = pkg.default;
const postqueen = new PostQueen(process.env.POSTQUEEN_API_KEY!);
```

## Fields the 1.0.4 types require

The types of version 1.0.4 mark a few fields as required that the API treats as optional, so TypeScript refuses a call without them. Send these values:

| Field | Send | What the API does with it |
|---|---|---|
| `posts[].group` | `''` | An empty group creates new posts. A group id that already exists replaces the posts that have it, so never reuse an old one by accident. |
| `posts[].settings` | The network's settings, or `{ __type: 'bluesky' }` for a network with none | PostQueen sets `__type` from the channel. What has to match is the shape of the settings. |
| `posts[].value[].id` | `''` | An empty id creates a new post. The id of an existing post changes that post instead. |
| `posts[].value[].delay` | `0` | Minutes to wait after the previous entry of a thread. |
| `postList({ customer })` | `''` | An empty customer lists the posts of every channel. |

Which settings each network takes is on [Posting settings by network](/public-api/providers/overview).

## Methods

| Method | Endpoint | Returns |
|---|---|---|
| `integrations()` | [`GET /integrations`](/public-api/integrations/list) | The parsed JSON body |
| `post(body)` | [`POST /posts`](/public-api/posts/create) | The parsed JSON body |
| `postList(filters)` | [`GET /posts`](/public-api/posts/list) | The parsed JSON body |
| `upload(file, extension)` | [`POST /upload`](/public-api/uploads/upload-file) | The parsed JSON body |
| `deletePost(id)` | [`DELETE /posts/{id}`](/public-api/posts/delete) | The raw `Response`, not parsed |

Every method but `deletePost()` is typed as returning `unknown`. Cast the result to the shape you expect, as the examples do.

### Post with an image and a thread

Upload the file first, then put its `id` and `path` on the post. The second entry goes out 5 minutes after the first.

```typescript upload.ts
import { readFile } from 'node:fs/promises';
import PostQueen from '@postqueen/node';

type Media = { id: string; path: string; status: 'ready' | 'processing' | 'failed' };

async function main() {
  const postqueen = new PostQueen(process.env.POSTQUEEN_API_KEY!);

  const media = (await postqueen.upload(await readFile('launch.png'), 'png')) as Media;

  await postqueen.post({
    type: 'schedule',
    date: '2026-10-01T09:00:00.000Z',
    shortLink: false,
    tags: [],
    posts: [
      {
        integration: { id: 'YOUR_CHANNEL_ID' },
        group: '',
        settings: { __type: 'bluesky' },
        value: [
          { id: '', content: 'The new calendar is live.', image: [{ id: media.id, path: media.path }], delay: 0 },
          { id: '', content: 'Drag a post to move it.', image: [], delay: 5 },
        ],
      },
    ],
  });
}

main();
```

`upload()` sends the file with a content type taken from the extension you pass: `png`, `jpg` and `gif` are mapped, anything else is sent as JPEG. That label does not matter. PostQueen reads the real type from the file itself, so an MP4 or MOV uploads fine. A video comes back with `status: "processing"`: wait until [Get media status](/public-api/uploads/media-status) says `ready` before you post it.

### One post on two networks with settings

WordPress and DEV each need a title. WordPress also needs the post type, here `posts`.

```typescript settings.ts
import PostQueen from '@postqueen/node';

async function main() {
  const postqueen = new PostQueen(process.env.POSTQUEEN_API_KEY!);

  await postqueen.post({
    type: 'schedule',
    date: '2026-10-01T09:00:00.000Z',
    shortLink: false,
    tags: [],
    posts: [
      {
        integration: { id: 'YOUR_WORDPRESS_CHANNEL_ID' },
        group: '',
        settings: { __type: 'wordpress', title: 'A calendar that shows everything', type: 'posts', status: 'publish' },
        value: [{ id: '', content: '<p>Drafts now sit next to scheduled posts.</p>', image: [], delay: 0 }],
      },
      {
        integration: { id: 'YOUR_DEV_CHANNEL_ID' },
        group: '',
        settings: { __type: 'devto', title: 'Why we rebuilt the calendar', tags: [] },
        value: [{ id: '', content: '## Why we rebuilt the calendar\n\nThree things changed.', image: [], delay: 0 }],
      },
    ],
  });
}

main();
```

### List and delete posts

```typescript list-delete.ts
import PostQueen from '@postqueen/node';

type ListedPost = { id: string; content: string; publishDate: string; state: string; group: string };

async function main() {
  const postqueen = new PostQueen(process.env.POSTQUEEN_API_KEY!);

  const { posts } = (await postqueen.postList({
    startDate: '2026-10-01T00:00:00.000Z',
    endDate: '2026-10-31T23:59:59.000Z',
    customer: '',
  })) as { posts: ListedPost[] };

  const res = await postqueen.deletePost(posts[0].id);
  if (res.status === 404) console.log('Already gone');
  else if (!res.ok) throw new Error(`Delete failed: ${res.status}`);
}

main();
```

A delete answers `{ "error": true }` when it works. Judge it by the status code, as above.

## Errors

The client does not throw when PostQueen answers with an error. It hands back the error body instead, such as `{ "msg": "Invalid API key" }`, or a `400` with `provider` and `message` when a post breaks a network's rules. Check the shape before you use a result:

```typescript errors.ts
import PostQueen from '@postqueen/node';

async function main() {
  const postqueen = new PostQueen(process.env.POSTQUEEN_API_KEY!);

  const result = await postqueen.post({
    type: 'schedule',
    date: '2026-10-01T09:00:00.000Z',
    shortLink: false,
    tags: [],
    posts: [
      {
        integration: { id: 'YOUR_CHANNEL_ID' },
        group: '',
        settings: { __type: 'bluesky' },
        value: [{ id: '', content: 'Shipping the new calendar today.', image: [], delay: 0 }],
      },
    ],
  });

  // The SDK returns the body of an error answer instead of throwing.
  if (!Array.isArray(result)) {
    throw new Error(`PostQueen refused the post: ${JSON.stringify(result)}`);
  }
}

main();
```

`post()` counts against an hourly limit per workspace, and `upload()` against 300 uploads an hour per workspace. Put several channels in one `post()` call rather than one call per channel. What each status code means is on [Limits and errors](/public-api/limits-and-errors).

## Calls the SDK does not wrap

Every other endpoint is a plain HTTPS call with the same header. Send the key as it is, with no `Bearer` prefix. This one checks whether an uploaded video is ready:

```typescript media-status.ts
const API = '{{apiBase}}';

type MediaStatus = { id: string; path: string; status: 'ready' | 'processing' | 'failed'; processingError: string | null };

async function mediaStatus(id: string): Promise<MediaStatus> {
  const res = await fetch(`${API}/media/${id}/status`, {
    headers: { Authorization: process.env.POSTQUEEN_API_KEY! },
  });
  if (!res.ok) throw new Error(`${res.status}: ${await res.text()}`);
  return (await res.json()) as MediaStatus;
}

mediaStatus('YOUR_MEDIA_ID').then(console.log);
```

The endpoints are listed in the sidebar under **Endpoints**, each with its request, responses and a playground.
