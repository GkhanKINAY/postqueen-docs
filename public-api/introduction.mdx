The public API does what the app does with posts: schedule and publish them on your channels, upload media, read analytics and manage channels. It is plain HTTPS and JSON, and everything in it acts on one workspace.

<div className="pq-visual pq-visual-fill pq-tint-green">
  <img noZoom src="/images/site/api-flow.webp" alt="A new blog post from an RSS trigger goes to PostQueen with POST /public/v1/posts, and PostQueen posts it to X, LinkedIn and Bluesky" />
</div>

| | |
|---|---|
| Base URL | `{{apiBase}}` |
| Authentication | Your API key in the `Authorization` header, as it is, with no `Bearer` prefix |
| Format | JSON in and out. Uploads are multipart form data |
| Who can use it | Any workspace with a subscription. The free trial counts |

## A first request

<Steps>
  <Step title="Copy your API key">
    <ApiKeyLocation />
  </Step>
  <Step title="List your channels">
    <CodeGroup>

    ```bash curl
    curl "{{apiBase}}/integrations" \
      -H "Authorization: YOUR_API_KEY"
    ```

    ```js Node.js
    const res = await fetch("{{apiBase}}/integrations", {
      headers: { Authorization: process.env.POSTQUEEN_API_KEY },
    });
    console.log(await res.json());
    ```

    ```python Python
    import os, requests

    res = requests.get(
        "{{apiBase}}/integrations",
        headers={"Authorization": os.environ["POSTQUEEN_API_KEY"]},
    )
    print(res.json())
    ```

    </CodeGroup>
  </Step>
  <Step title="Read the answer">
    Each channel comes back with an `id`. That id is what you pass to create a post, read analytics or run a tool.

    ```json
    [
      {
        "id": "cmg1ozx2c0000qz0h8c7w5v3n",
        "name": "PostQueen",
        "identifier": "bluesky",
        "picture": "https://cdn.example.com/avatar.png",
        "disabled": false,
        "profile": "postqueen.bsky.social"
      }
    ]
    ```

    <Check>
    A list of channels, even an empty one, means the key works. A `401` names what is wrong: see [Limits and errors](/public-api/limits-and-errors).
    </Check>
  </Step>
</Steps>

## Authentication

Every request to `/public/v1` carries one header:

```text
Authorization: YOUR_API_KEY
```

The value is the key itself. Adding `Bearer ` in front makes it an invalid key. The key belongs to the whole workspace and has no expiry: it works until an admin rotates it under **Connections > API Keys**, which ends the old key at once. Treat it as a password.

If you are building a product that other PostQueen users connect to, do not ask them for their key. Register an [OAuth app](/public-api/oauth): they approve it on a consent screen, and you get a `pos_` token that goes in the same header, also with no prefix.

| | API key | OAuth token |
|---|---|---|
| Acts on | Your own workspace | The workspace of the person who approved your app |
| Good for | Your scripts, automations and agents | A product other PostQueen users sign in to |
| Looks like | A random string | `pos_...` |
| Stops working | When an admin rotates the key | When the person revokes your app under **Connections > Approved Apps**, or leaves the workspace |

## Channels and integrations

The app says **channel**, the API says **integration**. They are the same thing: one connected account on one network. So `GET /integrations` lists your channels, and `integration.id` in a post is a channel id.

Each network has an identifier, such as `bluesky`, `wordpress` or `devto`, returned as `identifier` by [List channels](/public-api/integrations/list). A post's `settings` follow that network's shape: [Posting settings by network](/public-api/providers/overview). Which networks can be connected today, and which are In review or Soon, is on [Channels](/channels/overview).

## Limits

A workspace can send 30 `POST /posts` requests an hour, refused ones included, and each upload endpoint allows 300 requests an hour. Nothing else is limited. One request can carry many channels and a whole thread and counts once, so batch posts rather than sending them one by one. Details, headers and every status code: [Limits and errors](/public-api/limits-and-errors).
