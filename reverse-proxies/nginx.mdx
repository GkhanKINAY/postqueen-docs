Nginx takes more setup than [Caddy](/installation/domain-and-https#set-up-caddy) and gets its certificate from a separate tool, Certbot. Use it when Nginx already runs on the server. [Domain and HTTPS](/installation/domain-and-https) explains what the proxy is for.

## Before you start

- The domain's **A record** points at the server: `dig +short postqueen.example.com` prints its IP.
- Ports **80 and 443** are open. Certbot proves control of the domain over port 80.
- PostQueen answers on the server: `curl -I http://localhost:4007` returns `200`. If you run the image on its own with `-p 127.0.0.1:5000:5000`, use port 5000 wherever this page says 4007.

## Set it up

The commands are for Ubuntu and Debian.

<Steps>
  <Step title="Install Nginx and Certbot">
    ```bash
    sudo apt update
    sudo apt install -y nginx certbot python3-certbot-nginx
    ```
  </Step>
  <Step title="Write the site">
    Create `/etc/nginx/sites-available/postqueen` with your own domain:

    ```nginx /etc/nginx/sites-available/postqueen
    server {
        listen 80;
        listen [::]:80;
        server_name postqueen.example.com;

        # PostQueen accepts uploads up to 1 GB, sent in one request.
        # Nginx refuses anything over 1 MB unless this is raised.
        client_max_body_size 1G;

        location / {
            proxy_pass http://127.0.0.1:4007;
            proxy_http_version 1.1;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
        }
    }
    ```

    Then enable it and check the syntax:

    ```bash
    sudo ln -s /etc/nginx/sites-available/postqueen /etc/nginx/sites-enabled/
    sudo nginx -t
    sudo systemctl reload nginx
    ```
  </Step>
  <Step title="Get the certificate">
    ```bash
    sudo certbot --nginx -d postqueen.example.com
    ```

    Certbot proves the domain over port 80, then adds HTTPS to this server block and a redirect from HTTP to HTTPS. The package also installs a timer that renews the certificate and reloads Nginx on its own; `sudo certbot renew --dry-run` tests it.
  </Step>
  <Step title="Tell PostQueen its address">
    <ComposePublicUrls />

    <RestartService />

    <Warning>
    Skipping this step is the usual way to get a valid padlock and a sign-in that does not stick. The certificate is fine in that case; these three values are not.
    </Warning>
  </Step>
  <Step title="Check it">
    From your own computer:

    ```bash
    curl -I https://postqueen.example.com
    ```

    <Check>
    `HTTP/2 200` or `HTTP/1.1 200`, then a sign-in in the browser that holds.
    </Check>
  </Step>
</Steps>

The AI Copilot streams its replies and sends `X-Accel-Buffering: no`, which Nginx honors, so no buffering setting is needed. PostQueen uses no WebSockets in production, so no `Upgrade` headers are needed either.

## If it does not work

<AccordionGroup>
  <Accordion title="502 Bad Gateway">
    Nginx runs and nothing answers on the port in `proxy_pass`. `curl -I http://localhost:4007` on the server tells you whether PostQueen is up; if it is, the port in `proxy_pass` is wrong.
  </Accordion>
  <Accordion title="413 Request Entity Too Large">
    `client_max_body_size` is missing or too small in the server block that serves HTTPS. Certbot adds HTTPS to the block you wrote, so the value above carries over. If you wrote your own `listen 443` block, add the line there, then reload.
  </Accordion>
  <Accordion title="Certbot cannot validate the domain">
    The name does not resolve to this server yet, or port 80 is closed. Both have to be true while Certbot runs.
  </Accordion>
  <Accordion title="The page loads, sign-in does not stick">
    `FRONTEND_URL` does not match the address in the browser. See the step above.
  </Accordion>
</AccordionGroup>
